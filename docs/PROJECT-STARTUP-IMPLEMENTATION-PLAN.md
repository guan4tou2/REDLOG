## 決策
- 單欄最近專案列表、搜尋、建立新專案。沿用原有設計系統、字體、密度、品牌與原生視窗控制。已核對 project API 僅支援 open(id)，不加入任意資料夾開啟按鈕；保留重新命名與刪除。
- 專案列採明確可鍵盤啟動的開啟動作；無必要不增加選取後二次確認。方向鍵不得攔截其他按鈕/輸入。
- 名稱優先，次行顯示上次開啟，重名以路徑辨識。建立日期及容量不搶主要資訊。
- 建立 Modal 只需名稱，選填既有 profile 匯入；scope/network 仍由 Settings 擁有，避免重複建立表單。匯入保留警示布林值與所有既有欄位，不改變原始記錄邊界。
- 使用既有 Modal，圈限焦點、背景不可操作、關閉返回來源焦點。
- 重用 project API、解析器、儲存路徑與唯一識別碼；不得用 Date.now 或專案名稱取代後端契約。
- 匯入先解析及驗證暫存結果，再套用；無效/未知結構不清空草稿。錯誤持續顯示，不能默默丟項目後報成功。
- 名稱與已匯入設定在取消 Modal 後保留；目前不新增需先按＋的欄位，避免未加入文字遺漏。保留目前實際支援格式，不為原型新增不必要 API。
- loading/empty/no-results/error/busy/cancel 各有真實狀態；後端完成才說成功。連按不重複建立。
- 不加入假儲存就緒、版本、防篡改承諾、假視窗按鈕、裝飾紅點或 CDN。
## 步驟
1. 取得目前 main、讀 AGENTS/CLAUDE 及相關元件/API/測試；核對新 issues/specs 與原型差異。
2. 先保留現有正確行為，實作必要列表/建立流程改善，修正原型問題只在產品確實存在時動碼。
3. 加行為測試：按鈕 Enter、搜尋無結果、重名路徑、建立失敗/連按、匯入無效及草稿保留、焦點。
4. 依專案規範執行 gates；實際 Electron 檢查桌面/窄視窗/大字級/鍵盤、建立→開啟→重啟保存。
5. 更新本文件為實際完成與未驗證項目；不因測試通過宣稱完整 GUI QA。原先未授權 push 的限制已由使用者 2026-11-05「全部同步」授權取代；本次同步產品程式碼、測試與文件到 PR，未 merge 或 deploy。
