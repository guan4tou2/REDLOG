## 2. 批次 A：輸出完整性與閱讀（最高優先）
目標：同一指令無論輸出長短，使用者都能找到已保存的內容，且不混淆無輸出與未擷取。
關聯：#550、#546。

### A1 重現與分流
建立固定測試目錄，比較 ls、ls -al、超過16KiB輸出、stdout/stderr混合、零輸出及持續輸出。
分別測：內建 PTY、外部 Zsh/Bash 自動接入、明確 redlog-run；測線上接收與離線補送。
記錄 terminal bytes、command_id、inline/ref/io.cast/output_streamed、保存位置、內容 reader 結果。
不以命令列字串或是否有 -al 推定缺陷；先確認是擷取、歸因、保存還是呈現問題。
使用者版本/OS/來源是重現同一事故的必要資訊；尚未取得時先做隔離矩陣，不宣稱精確重現。

### A2 依證據修復
- 確定零長度 stderr 不顯示；stderr 未知/讀取失敗/截斷不能偽裝成空。
- 純空白輸出仍是真實內容，不用 trim 判空。
- streamed output 的讀取失敗、等待、完成與截斷使用同一套語意。
- cast 是合併 PTY 流，不虛構為獨立 stdout/stderr。先保證直接可達回放；文字投影若需要，另核對索引/分段/ANSI/跨事件範圍後實作，不能直接截取 JSONL 當文字。
- 活動、逐字稿、Inspector 與內容欄位使用相同狀態來源。

### A3 測試失敗診斷
relay-contract 必須區分 inline 與 command_output 聚合；只有證明產品契約正確才能修測試預期。
shell-token 測試需確認背景程序完成後再判定，不以零樣本當通過。
驗收：原始保存內容可核對、UI可讀/可回放、來源與專案正確；相關測試通過，範圍外失敗明列。

## 3. 批次 B：HTTP 設定到驗證完成
目標：使用者從「未驗證」能直接完成驗證並看到那筆流量。
關聯：#289、#435。
- 分清楚擷取服務、代理路由、CA信任、客戶端驗證、CDP連線；不以一個成功狀態代替全部。
- 驗證狀態與動作放在同一操作區；初始設置與設定頁共用流程，避免上下兩份重複狀態。
- CDP測試明確命名其用途，不讓使用者誤當HTTPS驗證。
- 驗證完成顯示客戶端/時間及開啟該紀錄；代理、CA、來源條件變更後按既有規則失效。
- 先在隔離埠測完整HTTPS流程；不停止使用者現有mitmdump、不占用既有工作流。
驗收：設定→實際客戶端HTTPS請求→nonce歸因→正確專案保存→HTTP詳情；另測逾時、CA錯誤、埠占用、重試、重啟及失效。
只有入口測試通過不得稱整體HTTP完成。

## 4. 批次 C：設定資訊架構與插件邊界
目標：每個操作有明確管理位置，從問題直接到對應來源。
關聯：#435、#557、#568。
先盤點每項控制的資料鍵、作用範圍、讀取來源、寫入動作與出現位置，再去重。
- 指令與終端：Shell接入/驗證。
- 瀏覽器與HTTP：代理、客戶端與驗證；進階連線參數收合。
- 其他擷取來源：以可直接定位的AI擷取、截圖、主機監看、外部來源群組呈現，不再增加一層分頁。
- AI擷取設定是來源接入與工作目錄授權；「AI對話」閱讀屬活動紀錄，文案與導向需區分。
- 插件管理：探索、本機安裝、更新、信任與診斷；專案擷取開關留來源頁。
- 全域安裝與專案授權的影響不可因減少點擊而隱藏。
先同步修訂 Spec062 US5/既有單一來源入口與 #568 的遷移要求，再實作插件與來源雙向定位。
驗收：從儀表板/插件異常一次定位來源；返回保留條件；沒有重複且語意衝突的開關；空/載入/失敗/鍵盤/窄視窗完整。
本批不新增Marketplace、第三方可執行宿主、全新設計系統。

## 7. HTML 參考稿（獨立交付）
目的：提供Stitch具體修改基準，不替代產品修復。
先完成一頁並落盤/驗證，再擴展，禁止全部寫完才保存。
1. 從現有React取tokens、布局、導航與元件，產出專案啟動單頁HTML。
2. 活動/時間軸/HTTP/設定等各頁分批輸出，附原元件對照。
3. 整合index導覽與離線資產，提供單頁檔及桌面/窄視窗截圖。
4. 現況與插件提案分開，無假daemon/安全狀態/狀態模擬器。
驗收：file方式可開、無CDN依賴、無JS錯誤、各頁非通用卡片換標題；搜尋/導覽/Modal可用且僅為示例，不假報後端成功。
若代理用量不可用，由主代理分頁完成，不以未落盤口頭進度代替成果。

### 第三批：簡化閱讀與 Stitch 交付（P2）

- 活動列表依日期分組，時間含時區；分別呈現結果與可靠耗時。第二行優先使用命中片段、工作目錄或有意義的摘要。時間軸聚焦並行、耗時與空檔。
- 全寬列表→按需開啟的 Inspector→全寬 Reader。Inspector 優先呈現事件、結果、必要預覽及下一步，次要 metadata 收合；各來源依適用欄位呈現。HTTP、Shell、證據及活動頁共用 Reader。截圖先顯示圖片，Scope 先顯示觀測與規則依據。
- 使用既有字級與設計元件，主要內容至少 13px。軌道採簡短來源名稱，長標題可在詳情閱讀；低頻操作收入次級選單，情境模擬控制只出現在展示模式。窄視窗採全寬詳情，驗收桌面、最小支援視窗、大字級及鍵盤路徑。
- 狀態列若顯示出口 IP 未驗證，提供檢視依據、驗證時間與對應操作；與 HTTP 擷取驗證分開。沿用第 7 節離線資產與整合 HTML 交付要求。
- 階段驗收依序核對原始測試資料、已保存內容、使用者實際讀到／取得的結果。Stitch 畫面用於視覺比對；產品完成以現有 Electron 入口實際操作為準。
