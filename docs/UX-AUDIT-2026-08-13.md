# UX 全面評估紀錄 — 2026-08-13

以 **v0.11.7** 為基準，對整個 renderer 逐頁（16 個視圖）做操作動線評估。切入問題：
「從每個功能與互動往下操作，是否能簡單直覺地完成、並取得需要的資訊？畫面佔比是否可調？」

本文是 [`UX-AUDIT-2026-08.md`](UX-AUDIT-2026-08.md)（2026-08-10 複雜度稽核）與 [`UX-TIMELINE-2026-08.md`](UX-TIMELINE-2026-08.md) 的續作，聚焦
**佔比／縮放（resize）**、**發現性（discoverability）** 與 **跨視圖一致性** 三條軸。
所有結論皆對照當前已提交程式碼親自核實；行號以核實當下為準。

配套的兩份設計文件：
- [`DESIGN-SYSTEM.md`](DESIGN-SYSTEM.md) — 統一色彩／字型／字級／icon／元件／版面框架
- [`DESIGN-TIMELINE-DISCOVERABILITY.md`](DESIGN-TIMELINE-DISCOVERABILITY.md) — 滾輪／軸切換發現性細部重設計

## 0. 總體判斷

RedLog 的視覺語言統一、資訊密度控制良好、鍵盤化程度高（`⌘1–9` 導覽、`⌘K` palette、`⌘.`
暫停錄製、HUD 角落吸附）。對「證據鏈稽核」這個核心任務，資訊呈現是稱職的。

兩個系統性弱點：

1. **畫面佔比幾乎全部寫死、不可調整**（§1）。
2. **重要操作藏在看不見的手勢／修飾鍵裡**，發現性差，靠原生 `title` tooltip 補救（§3、§4）。

Dashboard 與 HUD Overlay 是全 app 設計最成熟的兩處，可作為其他視圖的標竿。

## 1. 佔比／縮放（resize）— 最明顯的結構性缺口

| 機制 | 現況 | 位置 |
|---|---|---|
| 主視窗大小 | ✅ 可調、會記住（預設 1100×700，最小 800×500） | `src/main/windows.ts:10-15` |
| 全域 UI 縮放 | ✅ 有（Chromium `zoom` 0.9–1.5，Settings ▸ Advanced） | `src/renderer/src/main.tsx:11` |
| Sidebar 寬度 | ❌ 固定 140px，不可收合／拉寬 | `Sidebar.tsx:120` |
| 主內容區 vs Sidebar 佔比 | ❌ 純 `flex-1`，無可拖曳分割線 | `App.tsx:248` |
| Timeline 詳情面板高度 | ✅ **全 app 唯一**可拖曳縮放（上下），雙擊重設，存 localStorage | `Timeline.tsx:3571` |
| Timeline lane 標籤欄／minimap／事件列表 | ❌ 固定寬高（`LABEL_W`、`h-9`、18/22vh 寫死） | `Timeline.tsx:3530` |
| FindingsView 左欄 | ❌ 硬編 `w-80` | `FindingsView.tsx:98` |
| EventMarker 彈窗 | ❌ 硬編 `w-[420px]` | `EventMarker.tsx:72` |
| Terminal 分割窗（並排） | ❌ 只有分頁，不能左右／上下分割 | `TerminalView.tsx` |
| 跨視圖並排（如 Timeline + Terminal） | ❌ 一次只能顯示一個 view | `App.tsx:251-280` |
| 響應式佈局 | ❌ 全 renderer 僅 **1 處** `md:` 斷點；`grid-cols-3/4` 全寫死 | — |

**影響**：長 URL／note／loot preview 只能靠 `truncate`，操作者無法把某欄拉寬讀全值；
800px 最小寬度下 `grid-cols-3`（Dashboard 統計卡、Screenshots 網格）會擠壓。

**建議（依投報比）**：
1. **Sidebar 可收合**（icon-only ↔ 展開）＋記住狀態 — 成本最低、對小螢幕效益最大。
2. **共用 `<SplitPane>`**：Transcript 問答塊、FindingsView 左右欄、Loot 清單皆適用；佔比存 localStorage
   （Timeline 詳情面板已證明此模式在本專案可行）。
3. **Terminal 分割窗**：滿足「一邊跑指令一邊看時間軸」的高頻紅隊需求。
4. 關鍵格線補 `sm:`/`md:` 斷點。

框架化細節見 [`DESIGN-SYSTEM.md` §6 版面與縮放框架](DESIGN-SYSTEM.md)。

## 2. 逐視圖操作動線與合理性

### 2.1 完整視圖清單（16）
ProjectPicker、Dashboard、Terminal、Timeline、Transcript、Screenshots、Scope、Loot、
Marks(QuickMarks)、Settings、Search、Sidebar、StatusBar、Overlay HUD、EventMarker、IPStatusCard。
（"Targets" 側邊項不是獨立頁，是深連結到 Timeline 的 target 軸。）

### 2.2 標竿頁

**Dashboard** — IA 全 app 最佳。擷取健康卡用「例外報告」邏輯（只顯示壞掉的來源）、
dark/partial/healthy 三態、onboarding checklist + 單一主 CTA，回答「時間軸空的、然後呢」。
`App.tsx:373-593`。

**HUD Overlay** — glance 操作的典範：可拖曳、角落鍵盤吸附、`⚡` 快速標記（不搶焦點、inline `✓` 確認）、
pass-through 半透明但外部 IP 保持不透明、exposed 時整框紅色告警、內容自動 `autosize`。`OverlayApp.tsx`。

### 2.3 稱職但有小缺點

- **ProjectPicker**：最近專案一鍵開、進階設定收摺疊區不淹沒新手。**刪除專案無二次確認**。
- **Terminal**：多分頁、`⌘T/⌘W/⌘⇧[]`、字級 `⌘±`、per-pane 搜尋、關閉有確認、分頁顯示 cwd+exit code。
  唯一大缺點是**無分割窗**（§1）。
- **Transcript**：事件折成問答直讀、filter+kind chips+Export MD+跳 Timeline、標示「為何無輸出」四態。設計好，但不能調欄寬。
- **Settings**：五分頁（Capture/Scope/Evidence/OPSEC/Advanced）**均正常運作**，Advanced 用 5 個
  `Collapsible` 做漸進揭露，有設定內搜尋、auto-save。真實缺點見 §2.5。

### 2.4 Timeline — 痛點最集中

資料與泳道設計本身沒問題，問題在**互動發現性**。完整細節與重設計見
[`DESIGN-TIMELINE-DISCOVERABILITY.md`](DESIGN-TIMELINE-DISCOVERABILITY.md)。摘要：

- **滾輪行為取決於看不見的狀態**：無修飾鍵滾動時，泳道「有無溢出」決定它是平移時間軸還是垂直捲動；
  溢出與否隨視窗高度／泳道數動態改變（`lib/timelineWheel.ts:41`）。補救提示只在滾動當下閃 2.5 秒（事後通知）。
- **切到 target 軸會靜默讓整排 lane 篩選 chip 消失**（`Timeline.tsx:2924` 的 `laneAxis === 'source' &&` 條件）。
- **無 fit-to-window**：`100% ↺` 在 <2000px 寬視窗按了仍看不到全部（`baseTrackW` 下限 2000）。
- 雙擊只在 4px 把手有意義；Alt-click solo 泳道只寫在 tooltip；`↑↓` 走訪事件有「須先開詳情面板」的隱形前提。
- `⌘K` 開本地 palette、`⌘/` 卻跳全域 Search，分歧只寫在 `App.tsx:136` 註解。

### 2.5 Settings 的真實可改善點（已更正）
> 註：先前一份自動盤點誤讀舊版檔案，宣稱「三分頁空白／typecheck 紅／死碼」。經 `npx tsc --noEmit -p tsconfig.web.json`
> 實測乾淨、render 條件為新五分頁、i18n key 齊全，**該說法不成立**，不予採納。

- **auto-save + 手動「儲存」按鈕 + 「會自動儲存」提示三者並存**，訊號矛盾（`Settings.tsx:738-755`）；
  且儲存失敗被 `.catch(() => {})` 靜默吞掉（`:160`）。
- **搜尋涵蓋率低**：35 個設定群組有 16 個 `labelKeys: []`（約 46%），只能搜群組標題；
  搜「proxy／port／token／regex」等實際存在的欄位是零結果。
- **危險操作確認不一致**：只有「刪除操作員」有 `confirmDialog`（`:1789`）；
  **token rotate、revoke、匯入 profile（整包覆蓋設定，`:465-467`，無 diff 預覽）都沒有確認**。

## 5. 純函式測試縫（沿用本 repo TDD 慣例）

每項 UI 變更都應先落在一個純函式上，再接 UI（見 [`DEV-REQUIREMENTS-capture-onboarding.md`](DEV-REQUIREMENTS-capture-onboarding.md)）。本輪建議的縫：

- `splitPaneClamp(px, min, max, containerPx)` — 分割線位置夾擠（複用 Timeline 詳情面板既有邏輯）。
- `settingsSearchIndex(groups)` — 由 group 定義＋i18n 產出可搜尋 term（含 hint），取代手維護的 `labelKeys`。
- `emptyStateFor(view, ctx)` 擴充 `filtered-empty` 分支（C3）。
- `wheelMode(ctx)` 已存在（`lib/timelineWheel.ts`）；發現性重設計在其之上加 `wheelModeLabel(ctx)`。
