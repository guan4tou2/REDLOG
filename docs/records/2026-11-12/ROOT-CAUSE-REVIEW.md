### 後續兩份審查的決定（同日）

依 [08 外掛系統](root-cause/08-plugin-system.md) 與 [09 設定時的選擇與多重性](root-cause/09-setup-choices-and-multiplicity.md) 各自列出的五個問題，全數照審查者的建議採納。以下是決定，不是已完成的實作；實作順序由工作計畫安排。

| 項目 | 決定 |
|---|---|
| 第三方來源的安裝 | 第三方 Source 只允許手動設定（`manual`）；RedLog 不把第三方腳本寫進 shell rc 或其他工具的設定。內建 hook 不受影響 |
| 官方 AI 整合 | 取消機器層的「安裝」；adapter 從 app 本體執行，第一次在某專案啟用時以原生對話框取得同意。外掛頁只保留撤回同意 |
| 未登記的事件種類 | 外掛宣告、但不在核心表上的 subtype 預設寫入 logged 層，由核心的表升級特定種類；heartbeat 不是事件 |
| 內建 pack 的機器層停用 | 刪除 `state.json` 對 bundled pack 與 starter-pack 的停用；既有的停用旗標轉成一次性通知 |
| 外掛的簽章欄位 | 移除 `signature`／`publisher`；信任只看本機的內容雜湊 |
| Hook 的安裝範圍 | 預設裝到本機所有有 adapter 的 shell；每個寫入的檔案保留精確的還原紀錄，並以 hook 啟動時送出的訊號作為「有載入」的證據 |
| 被切換專案的終端 | 改為暫停：回到綁定的專案時自動恢復並寫入 `capture_resumed`。「A 的指令不歸到 B」不變；`redlog stop` 仍是永久的 |
| 抽不出目標的指令 | 標註目標的來源（`target_via`）；每個終端沿用自己最近一次抽出的目標。全域的目前目標只用於標記與手動截圖 |
| Shell 啟動時的輸出 | 初始化期間不輸出。只在狀態改變時於下一個 prompt 印一行到 stderr；「已載入」改由 `redlog status` 與 app 的 shell 列呈現 |
| 機器或個人層級的設定 | 新增機器層級的設定檔（`~/.redlog/machine.yaml`）；專案只保存該次任務的事實或明確覆寫的值 |

## 5. 未確認

各報告自己列出的未確認事項仍然有效，動手前需在對應環境確認。跨報告較重要的幾項：

- 暫停期間當機後重開，暫停時輸入的指令是否被補進正式紀錄（01-F4）。
- 主行程停頓時 curl 逾時，事件是否既寫入又暫存（01-F2）。
- 過短的 NTP 封包是否使主行程拋出未捕捉的例外（05-F4）。
- 離線且未開離線模式時，錨定失敗是否使「前後事件」面板顯示拒絕（07-F2）。
- 儀表板的證據鏈不一致紅字在正常擷取期間是否閃現（03-F3）。
- Windows 上「每次落在不同檔案」的失敗是否為整機停頓（06-F2）。
- 02 的絕對數字在高負載的機器上量得，比例可信，絕對值偏高。
