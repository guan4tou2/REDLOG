## #326：WSL 來源選擇

### 準備

在 WSL 發行版內操作，Windows 版 RedLog 保持執行。發行版的 `~/.redlog` 需含 `api-port`、`api-token` 兩個檔案；`api-port` 填入 Windows App 實際監聽的 port（可從 `%USERPROFILE%\.redlog\api-port` 取得）。

| ID | native 狀態 | 設定方式 | 預期 | 結果 |
| --- | --- | --- | --- | --- |
| D1 | port 不可達 | `api-port` 填一個沒有服務的 port（例如 `1`） | 回退 Windows profile；事件進 Windows 專案 | NOT RUN |
| **D2** | Health 200、Whoami 401 | `api-port` 填 Windows App 的 port，`api-token` 填一個該 App 不接受的舊 token | **回退 Windows profile；事件進 Windows 專案，不進 `~/.redlog/pending`** | NOT RUN |
| D3 | native token 有效 | 發行版內執行 Linux 版 RedLog，`api-port`／`api-token` 指向它 | 保留 WSL native 來源；事件進該 Linux 專案的資料庫 | NOT RUN |
| D4 | Whoami 503 | Windows App 執行中但未開啟專案 | 維持目前目錄選擇；**不宣稱 token 已驗證** | NOT RUN |

D2 是本 Issue 的主要驗收案例。D1 只能證明「來源消失會回退」，照不到 mirrored networking 的核心情境：port 有服務回應、health 200、token 已失效。

### D4 的已知限制

`src/core/api-server.ts` 的順序是 `if (!projectOpen) → 503` 先於 `authenticate() → 401`。所以 App 開著但沒有專案時，過期 token 拿到的是 503，token 無法判定，`hooks/shell-common.sh` 刻意保留 native 目錄。此情境下的過期 token 風險**未完全排除**，不得記為已驗證。

`Commit` `55567a58`、`Installer` 的 SHA-256、Windows 版本、WSL 發行版與核心版本、是否啟用 mirrored networking、執行指令、實際入庫的 Event（DB 或 Activity 截圖）、`~/.redlog/pending` 的檔案數變化。

## #345：Git Bash 送出

### 準備

Windows 上以 Git Bash 作為來源（App 由 Git Bash 啟動，或內建終端開 Git Bash）。記錄前後比對 `%USERPROFILE%\.redlog\pending` 的檔案數。

| ID | 環境 | 預期 | 結果 |
| --- | --- | --- | --- |
| G1 | `MSYS_NO_PATHCONV=1` | 事件直送，`createdAt` 與 `source_timestamp` 差距在數百毫秒內；`pending` 不增加 | NOT RUN |
| G2 | 預設環境（不設 `MSYS_NO_PATHCONV`） | 同上，無回歸 | NOT RUN |
| G3 | G1 環境下重啟 App 後再送 | 仍直送，不因重啟改變 | NOT RUN |

### 每筆記錄

`Commit`、`Installer` SHA-256、Git Bash 版本（`git --version`）、指令、`source_timestamp` 與 `createdAt` 的差值、`pending` 前後數量、實際入庫的 Event。
