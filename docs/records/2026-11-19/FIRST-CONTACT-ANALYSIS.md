## 一、最重要的結論

兩位都能在幾分鐘內開始記錄，也都說核心設計是對的。會讓人放棄或不信任的不是畫面太亂，而是下面這類：**畫面說的和實際發生的不一樣**。

### 兩位都撞到的

1. **匯出說「完成」，內容卻不是你以為的。** 新手：預設是「目前篩選結果」，沿用了別頁按過的篩選，得到只有 15 筆測試資料的檔案。資深：刻意限定目標和時間，得到「包含 0」，因為目標是本機位址，被預設的「非工作流量」清單丟掉。
2. **範圍內的本機位址被當成非工作流量**，在活動、HTTP、戰利品三個畫面隱藏，每次啟動重新隱藏，並從匯出丟棄。實務上 port-forward 和 pivot 每天都會讓真實目標變成 `127.0.0.1`。兩位都因此以為指令沒錄到。
3. **不知道自己有沒有在被記錄。** 點一下狀態列的「錄製」就暫停；暫停後儀表板還寫「正在運作 · 可用」；重開 app 停在專案清單、什麼都不錄；`redlog status` 在暫停、app 關閉、沒開專案三種情況都印「recording enabled」。資深因此無聲遺失四個指令，紀錄裡沒有缺口。
4. **機密看起來有遮罩，其實沒有。** `curl -u admin:密碼` 和 `ghp_` token 沒被偵測，以明文存在資料庫和匯出檔；`mkdir -p ~/tmp` 卻被標成密碼。遮罩蓋住的是變數名稱。
5. **安裝 hook 會改 `~/.zshrc`，按下之前沒有說檔名和內容**；說明寫「指令與結束碼」，實際裝的還包含輸出轉送。
6. **驗證結果嚇人且不準。** 「✓ 證據鏈完整 ✗ 最後一次錨定失敗 +1」；儀表板寫「客戶驗不過」，但驗證器是通過的。匯出檔附的 `verify.sh` 用 macOS 內建 Python 會印 `AUTHENTICATION FAILED`，只因缺一個套件。
7. **輸出明明有錄，畫面說沒有；沒錄到，畫面說有。** 超過約 1 秒的指令，閱讀器和搜尋都顯示「未擷取此內容」（輸出其實在磁碟上，「輸入／輸出」分頁看得到）。反過來，`nc` 的輸出沒錄到，卡片卻寫「已保存內容」。

### 只有資深在意，但會讓工具直接被淘汰的

8. **沒問就對外連線，而且介面上關不掉。** 第一次開專案：五個查外部 IP 的服務（之後每 60 秒）、NTP、30 秒後三個 OpenTimestamps 伺服器。離線模式只存在於 YAML 的一個鍵。資深的結論：「不能在客戶網路上啟動。」
9. **每個指令慢約 240 ms，app 關著也慢 190 ms。** 每個指令啟動一個 `python3` 和兩個 `curl`。這是他過去放棄同類工具的原因。
10. **範圍只是標籤，而且不精確。** `from`、`SoW`、`B` 這種單字會變成授權主機；`host:8443` 被拒絕；明確排除的和沒列入的都顯示「範圍外」；超出範圍時終端機和 HUD 都沒有提示。

### 不要弄壞的（兩位都不用想就會用）

- zsh hook 幾乎看不見：TTY、Ctrl-C、管線、heredoc、巢狀 shell 都正常；`redlog stop/start` 每個終端各自有效；解除安裝後 `.zshrc` 逐位元組還原。
- app 沒開時終端機那一行「RedLog 無法連線，這個終端機沒有被記錄」。
- 活動紀錄的「指令」篩選、「輸入／輸出」逐字稿與複製成 Markdown、HTTP 找 5xx。
- 首次設定的回音檢查，兩秒內「✓ 已驗證」；`⌘⇧M` 標記。
- 離開、刪除、結束的確認對話框，寫明會停掉什麼。
- 匯出摘要列出丟棄、遮罩、暫停的數量；匯出檔的 README 寫明它不能證明什麼。

### 兩個最多人會問的問題

- **在不回顯的密碼提示輸入的密碼，沒有被存在任何地方。** zsh、bash、內建終端機、以及用 PTY 記錄器包住的連線裡都測過，然後搜尋整個專案目錄。轉送程式不讀鍵盤輸入，錄影只錄輸出。寫在指令參數裡的密碼（`curl -u`）則以明文存在。
- **oh-my-zsh + powerlevel10k 的環境沒有問題。** hook 加在設定檔最後；沒有觸發即時提示警告；自動建議與語法上色照常（只能從文字層面確認）；解除安裝後逐位元組還原。

### 支援良好（不要弄壞）

指令原文（here-doc、續行、貼上、中文、5,000 字元）；歷史展開；結束碼；tmux（分割、視窗、卸離、調整大小）；背景工作的延遲輸出；和其他 `precmd`／`preexec` 使用者、既有的 `tee` 記錄器共存；真實工具（nmap、ffuf、sqlmap、hydra）完整記錄並歸到目標；受管代理保留完整請求與回應、把每筆流量連到指令，經過兩層 mitmdump 模擬的 Burp 串接，兩種順序都不重複；連續 300 個指令與兩個終端同時執行沒有遺失、順序正確。

### 弄壞終端機的（資深工程師放棄同類工具的頭號原因）

這些都動到 `hooks/`：一次修一項，每項獨立審查。守這條路徑的測試需要 PTY 與本機 listener，在沙箱裡會安靜跳過。

- **T1**（#849） 輸出順序被打亂：`echo a; echo b >&2; echo c` 印出 `a c b`。
- **T2**（#850） `echo hi |& less` 無法離開。
- **T3**（#851） `sleep 20 &` 之後 `echo $!` 是 hook 輔助程序的 PID。
- **T4**（#852） bash 3.2：`${PIPESTATUS[@]}` 遺失、`$_` 變成 hook 的函式名、`jobs` 出現不存在的工作、`time` 多 0.2 秒。
- **T5**（#853） zsh ▸ bash ▸ zsh：最內層「Stopped (tty output)」。
- **T6**（#854） `exec zsh` 留下一筆永不結束、重複所有內容的紀錄。
- **T7**（#855） 混用重導的指令，畫面上的輸出遺失。
- **T8**（#856） 每個指令慢 173–229 ms；`redlog stop` 後 0.4 ms；app 關著仍 195 ms。（即 F10）

### 紀錄誤導的

- **R1** 20 萬行輸出在中間被截斷 49 處（丟掉約 40 萬位元組），標頭寫「不完整」，但閱讀器把缺口隱藏，看起來是連續的。 → **已合併（#848：在缺口處標示）**
- **R2**（#857） app 結束或終端機關閉時還在跑的指令，只留下開始，永遠沒有結束與結束碼。
- **R3**（#858） 目標判斷錯誤：`cd /tmp && nmap … 127.0.0.1` 抓不到；`-oN scan.txt` 把檔名當目標；迴圈裡抓到字面上的 `$h`；真的超出範圍的主機反而漏掉。
- **R4**（#871） 終端搜尋的 `status:500` 是字串比對，命中的是查詢指令本身。
- **R5**（#870） 沒走代理的工具讓 HTTP 歷史是空的，畫面沒有說原因。
- **R6**（#866） 被拒絕的 `ssh` 記成「Pivot」；任何 `-p` 旗標記成憑證（即 D5a）。
- **R7**（#870） 時間軸的終端列只叫 `zsh <PID>`，分不出誰是誰。
- **R8**（#871） `POST /api/marker` 忽略 `target` 欄位（文件已由 #839 更正為 `target_id`；API 是否接受別名屬 D20）。

### 需要擁有者決定的（習慣矩陣帶出）

- **D32 分頁程式被關掉且沒有說**（#873）：hook 把 `PAGER`、`MANPAGER`、`GIT_PAGER` 設成 `cat`，`man ls`、`git log` 會一次倒出來。這是刻意的設計（為了錄到輸出）。選項：分頁類指令改走原生終端（不錄內容、只記有執行），或維持並在安裝時說明。
- **D33 app 沒開時的指令直接遺失**（#873）：`~/.redlog/pending` 目錄存在但是空的；只有 app 有回應但拒絕時才會暫存重送。選項：app 連不上時也暫存，之後重送；或維持遺失，但在紀錄裡留一筆「這段時間有 N 個指令沒錄到」。兩者都會讓 hook 自己回報的內容進入證據鏈。
- **D34 連線裡的工作**（#873）（`redlog-session -- ssh …`）：整段連線是一筆，裡面打的指令找得到（全文搜尋與逐字稿），但不是逐筆紀錄，連線裡的 `curl` 不會產生目標、範圍或 HTTP 事件。這是設計上的界線；建議至少在連線開始的那行提示裡說明。
- **D35 遠端主機的警告只在 README**（#873）：不該把 token 複製到 VPS 的說明，在 app 裡找不到（設定頁搜尋 remote、ssh、VPS 都沒有）。建議放在 hook 設定頁和 token 旁邊。
- **D36 從終端機附加證據檔**（#873）：目前只有自動偵測的 `curl -o` 和匯出，沒有「把這個檔案加成證據」的終端指令；`nmap -oA` 產生的檔案也不會被提供或雜湊。這是新功能。
- **D37 沒有 hook 的 shell**（#873）（`sh`、fish、nushell）：裡面的指令沒有紀錄也沒有提示，介面上從未提過 fish。建議在偵測到時說一句，不做 fish 的 hook。
- **D38 純終端機的入口**（#873）：整個任務可以只用 `redlog` 指令加本機 API 走完，回應都是乾淨的 JSON；但 `redlog-cli` 不在安裝版裡，埠號與 token 檔的位置產品從未告知，app 重啟後埠號還會變。選項：把 CLI 包進安裝版並在設定頁列出，或在 `redlog help` 印出 API 位置。

### 需要擁有者決定的（#844 審查與後續帶出）

- **D39 範圍比對只看主機，不看埠**（#868）：範圍寫 `127.0.0.1` 時，`127.0.0.1:8443` 的轉發和 `127.0.0.1:11434` 的無關本機服務一起算範圍內，匯出也一起帶出（含 HTTP 內容）。設定頁的文字是真的，但沒說是整台主機所有埠。選項：接受並在預覽顯示「因範圍而納入的本機紀錄」筆數；或讓範圍條目可以帶埠（即 D9b）。
- **D40 `127.0.0.1` 在範圍內不等於 `localhost`、`::1`**（#868）：用 `curl http://localhost:8443` 的人會再碰到被隱藏的問題。選項：三者視為同一台；或維持字面比對。
- **D41 API 匯出不套用「匯出時丟棄非工作紀錄」**（#871）：設定頁那個選項對 API 匯出（HAR、證據包）不成立。建議修成一致（和 D21 同一區）。
- **D42 篩選條件跟著換頁**（#870）：在活動紀錄按了「指令」，到 HTTP 頁清單就是空的，雖然有說明框。這是規格 033 的既有行為。選項：維持並把標題改成和內文一致（#848 已改）；或讓不適用的條件在該頁不生效。
- **D43 終端搜尋的 `status:500`**（#871）：現在是字串比對。選項：做成結構化條件；或遇到這種寫法時回錯誤並指向 HTTP 頁。

- **D44 驗證結果那一行的「+N」**（#869）：驗證完幾秒後就會出現「+1」（app 每分鐘寫一筆 IP 狀態事件），所以畫面幾乎不會顯示「全部已驗證」。程式碼註解說這是刻意顯示的，所以沒有動。選項：維持；或只在詳情裡顯示；或不把 app 自己寫的例行事件算進去。
- **D45 詳情面板開著時，摘要列和面板重複同一筆資訊**（#870）：時間軸底部版面在小視窗時兩者各佔一塊。#846 修掉了重疊，重複還在。選項：面板開著時收起摘要列（「閱讀」「在活動紀錄開啟」要搬進面板標題列）；或維持。

### 無法測試（需要另外的機器或安裝）

Linux（Kali）與 Windows 的 shell；macOS 上的 fish、nushell、PowerShell；真實的圖形終端機（iTerm、Ghostty、Warp——Warp 有自己的 shell 整合，最可能衝突）；真實的 Burp、ssh、msfconsole；HTTPS 攔截；AI 代理、tcpdump、主機監看等擷取來源。

### 測試隔離的教訓

假家目錄擋不住所有東西。第一部分的實測有四類操作碰到了隔離以外的環境，第二部分明文禁止後沒有再發生：

- `screen` 不理會 `HOME`，會寫到真實的 shell 歷史檔。
- `ssh <使用者>@localhost` 連到的是本機真實的 sshd。
- `pkill -f <樣式>` 會比對到測試以外的程序。
- powerlevel10k 會嘗試下載 `gitstatusd`。
