## 2. 需求與規範的單一清單

每一項後面是它的權威出處。這裡只列結論。

### 2.1 產品

- 永遠單人、本機；本機的簽章紀錄是唯一的證據。多人多機在 app 之外，只經使用者自行安裝的上傳外掛連接。（DECISIONS §2）
- 以資深滲透測試者的角度判斷功能：RedLog 附著在操作者自己的終端機、代理、瀏覽器上；自己的替代品是選用的，預設關閉。（DECISIONS §1）
- 不做報告產生、不做發現管理；不預設操作者使用哪些工具。
- 每個決定同時改善使用者、開發者、代理三種體驗；首屏三秒內看懂是做什麼的。（UI 標準 §26）

### 2.2 擷取與證據

- 所有寫入經同一個寫入契約，由接收端蓋上來源身分。（Spec 071）
- 暫停：即時入口依收到時間判斷；暫存檔在暫停期間不處理，恢復後只採信通過驗證的來源時間與已記錄的暫停區間；不使用檔案修改時間。（DECISIONS §6、Spec 071）
- 遺失先記帳再發生；每個檔案恰好一個結果；隔離區依專案分開。（Spec 071）
- 出口位址進每一筆新事件並附讀取時間；不知道時不顯示安全。（Spec 071 修訂、Spec 075 FR-025、#728）
- 擷取不得靜默停止；來源狀態固定八個詞，整體狀態四個。（Spec 075）
- 私人內容：可設為私人的 shell、匯出時遮蔽、明確的「清除內容」操作。（根因審查 §4）
- 擷取來源屬於這台機器；專案只決定範圍、綁定、暫停。AI 工具是例外：工作階段屬於哪個專案需逐專案選擇且可改。（DECISIONS §2、§6a）

### 2.3 擴充功能

- 比照程式編輯器：manifest 宣告、內建可停用、需要時才啟動、獨立主機行程；類型為 Source、Processor、Exporter。（Spec 076）
- 基礎功能留在核心；只把搬動後不影響基礎功能的部分改成擴充功能；第一階段不搬證據寫入路徑上的任何東西。（DECISIONS §6a）
- API 與相容政策現在定完整：穩定等級、版本協商、淘汰政策、不相容時的固定狀態。（Spec 076、`contracts/extension-api-v1.md`）
- 五條不可照搬：只能新增事件；真相介面不可被取代或遮蓋；讀取需授權並留紀錄；更新需重新核准；不做市集、不自動更新。
- 讓別人做自己的工具，分三層：外部工具（讀取 API、貢獻指令、深連結，穩定）；宣告式（自己種類的篩選與閱讀器，穩定）；沙盒面板（依 webview 模式，一個分隔線下的導覽入口，等級待裁定，建議實驗）。（Spec 076 J 段）
- 擴充功能不碰 app 的畫面；狀態列項目、版面重排、自訂閱讀器不提供。核心補四個通用閱讀器（表格、十六進位、差異、鍵值）。
- 擴充功能的設定：以 schema 宣告、核心繪製、兩個層級擇一、機密存系統憑證庫、缺必填時該來源為「未設定」、立即生效。操作性的控制不是設定。（Spec 076 K 段）

### 2.4 介面

- 導覽：活動紀錄、時間軸、目標、證據、設定；選用來源與已核准的面板在分隔線下。不新增核心頁面。
- 活動紀錄：頂端一行狀態讀數，就地展開；固定篩選列 指令｜HTTP｜AI｜檔案｜標記；HTTP 與書籤是篩選而非頁面。
- 一頁一個主動作；次要入口收合；刪標語、提示文字、次要標籤。
- 版面：一個內容欄（上限 1120px、置中），所有元素對齊左右邊；列高 36px；無圓角；8px 節奏；風格元素只取有功能的。
- 每一筆打開看得到內容與其完整程度；一個標記動作；匯出只有一處。
- HUD 保留全部功能。
- 首次使用是照著做就完成的清單，每步以證據打勾。

### 2.5 設定與尋找（2026-11-13 稍後；尚未寫入規格）

- 在哪裡看到就在哪裡改：來源的操作與綁定、安全 IP 在活動紀錄的狀態展開區；範圍在目標頁。
- 設定頁是一頁平鋪，只放設一次的值。這個專案：輸出上限、保留期限、戰利品規則。這台機器：擴充功能、HUD 顯示、快捷鍵、時間顯示、版本。
- 找東西兩條路：狀態讀數上看得到的就能點；全域 ⌘K 依名稱到任何頁面、設定列、來源列或擴充功能貢獻的指令。設定頁內不另做搜尋。
- 檢驗標準：新使用者從安裝到完成第一次任務，不需要打開設定頁。
- 依程式碼現況，快捷鍵目前不可改（只能唯讀列出），介面沒有主題系統（不列「主題」）。（Spec 076 的對照表）

### 2.6 工程

- 推送前五道檢查，順序固定；CI 另有跳過數基準。（`CLAUDE.md`）
- 動到索引、鏈、匯出、寫入路徑的變更，開 PR 前先做獨立的對抗審查。
- 一次只跑一個測試行程、限制工作數、不做壓力迴圈。
- 規劃與審查、實作分由不同的代理進行；實作者的「失敗來自環境」需逐檔對照乾淨的 `main`。

## 4. 尚未涵蓋的功能與設計

以下是對照已有決定後找出的缺口。都是觀察，未經逐項查證程式碼。

| # | 缺口 | 為什麼重要 |
|---|---|---|
| 1 | **操作者不看 app 時，擷取失敗怎麼讓他知道** | 操作者在自己的終端機裡工作。HUD 可關，狀態讀數在 app 內。需要定義：終端機提示字元上的一次性通知、系統通知、HUD 各在什麼條件下出現，以及不能被關到完全靜默的底線 |
| 2 | **同時進行兩個任務** | 目前一次只開一個專案。資深測試者常同日處理兩個委託；終端機綁定已是逐專案的概念，但沒有定義「未開啟的專案的終端機送來的事件」怎麼處理 |
| 3 | **任務結束** | 沒有「結束專案」的定義：封存、解除終端機綁定、撤銷遠端主機的寫入憑證、移除遠端 hook、保留期限起算 |
| 4 | **靜態加密** | 專案資料庫與內容附檔含客戶資料，存在筆電上。未決定是否加密、金鑰放哪、遺失怎麼辦 |
| 5 | **簽章金鑰的生命週期** | 輪替、備份、外洩後的處置、換機；第三方驗證工具未隨安裝包附帶 |
| 6 | **專案搬到另一台機器** | 來源改為機器層級後，專案在另一台機器開啟時來源全部不存在；需要定義唯讀開啟與重新綁定 |
| 7 | **磁碟空間** | 長時間任務的 cast、封包、HTTP 內容會持續成長。未定義配額、將滿時的行為、滿了之後的帳務 |
| 8 | **移除與還原** | 解除安裝時還原 shell 設定檔、清除機器層級設定與憑證；目前只有個別來源的移除 |
| 9 | **匯出時遮蔽** | 多處決定以它為前提（上傳外掛、外部工具讀取內容、面板讀取內容），但還沒有規格 |
| 10 | **時鐘** | 遠端主機與本機時鐘不一致時的呈現；目前只有「拒絕不可信的來源時間」，沒有「顯示偏差多少」 |
| 11 | **問題回報** | 不含客戶資料的診斷包：版本、來源狀態、最近的錯誤、擴充功能清單 |
| 12 | **版本升級** | 記錄中升級 app、資料庫結構遷移與降版、升級期間的缺口帳務 |
| 13 | **巢狀工作階段** | tmux、screen、ssh 內再 ssh 時的終端機身分與綁定 |
| 14 | **平台一致性** | PowerShell、WSL、Linux 的首次使用清單與來源狀態是否等同；e2e 只在 Ubuntu 執行 |
| 15 | **各頁的空、載入、錯誤狀態** | 模板只畫了活動紀錄的空狀態 |
| 16 | **鍵盤與無障礙** | 全鍵盤操作的完整性、對比、縮放；⌘K 成為主要尋找途徑後更重要 |
| 17 | **真人驗證** | 目前所有流程判斷來自讀程式碼與模板；沒有任何一項經操作者實測（#593、#457 仍開著） |

建議的處理順序：1（靜默失敗的通知）與 9（匯出時遮蔽）先成規格，因為現有決定已經依賴它們；3、4、5、6 合成一份「專案生命週期與保管」規格；其餘併入既有規格的任務或追蹤單。
