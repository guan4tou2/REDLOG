## 1. 判斷功能的原則

以資深滲透測試者的角度判斷每個功能：這個人已經有自己的終端機、代理、瀏覽器與筆記方式，
不會把工作搬進 RedLog。RedLog 記錄他在那些工具裡做的事；RedLog 自己提供的替代品是選用的。

## 2. 產品邊界

| 項目 | 決定 | 取代 |
|---|---|---|
| App 的使用者 | 永遠單人、本機；本機的簽章紀錄是唯一的證據 | —（重申） |
| 多人多機 | 不在 app 內。多人多機的收集系統（ELK 一類）是 app 之外的東西，兩者之間只靠使用者自行安裝的上傳外掛連接 | 不改變「不做中央架構」 |
| 團隊對帳 | 先做可機械對齊的匯出（UTC、出口、終端、主機、目標、指令、事件 id）；上傳外掛排在其後，且以匯出確實套用遮蔽為前提 | — |
| 擷取來源的層級 | **擷取來源屬於這台機器**，不隨專案改變。專案層級只決定：範圍、哪個終端或工作階段綁定到這個專案、暫停 | 取代「來源依專案啟用」（Spec 075 的三值啟用、Spec 071 FR-07A、Spec 073 的專案層同意與 Q2） |
| 內建終端機、擷取瀏覽器、受管代理 | 降為選用，預設關閉；不在預設導覽與首次使用的主線上 | 取代 Spec 075 US1 中內建終端機預設啟用 |

## 3. 外掛（擴充功能）模型

| 項目 | 決定 | 取代 |
|---|---|---|
| 管理方式 | 比照程式編輯器的擴充功能：manifest 宣告貢獻、內建擴充功能隨附但可停用、需要時才啟動、獨立的擴充功能主機行程 | Spec 075 的外掛管理部分 |
| 類型 | Source、Processor、Exporter | 取代「去掉 Exporter」（Spec 075 Q5） |
| 模組導向 | 所有擷取來源重構為外掛（內建擴充功能）。核心保留：寫入入口與蓋章、雜湊鏈與簽章、儲存、查詢、來源狀態的計算、閱讀器、驗證與匯出封存 | 取代根因審查 §3「不把內建來源改成外掛」 |
| 介面擴充 | 擴充點在 manifest 與主機設計中預留，**目前不開放**：外掛只能指名核心提供的閱讀器。不做市集，不自動更新 | 維持「外掛不提供介面」 |
| 不可照搬之處 | 外掛只能經寫入契約新增事件，由核心蓋上來源；核心的真相介面（記錄狀態、完整性、來源狀態）不可被取代或遮蓋；讀取需授權並留紀錄；更新需重新核准 | — |

## 6a. 同日稍後的修訂

擁有者對 §2、§3 的三點修訂，以這裡為準：

| 項目 | 修訂 |
|---|---|
| AI 工具是「來源屬於機器」的例外 | AI 工具的安裝與啟用在機器層級，但哪個工作階段屬於哪個專案需要選擇，而且可以重新選擇：專案或工作階段（工作路徑）的選擇維持在專案層級，如同現行做法。一般化的說法：來源屬於機器；資料流不自然對應單一專案的來源，需要明確的專案綁定步驟，重新綁定是正式的動作 |
| 外掛化的範圍 | 不是全部改成外掛。**基礎功能保持原樣**；只把搬動後不影響基礎功能的部分改成外掛。逐一依程式碼判斷：搬動會碰到基礎路徑的，先留在原處。第一階段只做不改行為的抽離，不搬動證據寫入路徑上的任何東西 |
| 介面與相容性 | **現在就定完整**，不留到以後：manifest 與擴充功能主機 API 的完整第一版、版本與相容範圍、破壞性變更的定義與淘汰政策、各介面的穩定等級（穩定／實驗／保留）、不相容時的行為（來源列顯示固定狀態與原因，不靜默停止擷取，遺失要記帳）。介面擴充點現在就定義形狀並標為保留，使日後開放是新增而不是重做 |
