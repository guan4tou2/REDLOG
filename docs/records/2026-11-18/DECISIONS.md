## 2. 展開態的說明文字減少

### 擁有者的話

看到設計稿的展開態後：

> 說明文字稍微多 思考如何簡化

擁有者逐項選了三個選項（選項文字由協調者寫）：

| 項目 | 擁有者選的選項 | 內容 |
|---|---|---|
| 鍵值表 | 「拿掉重複三列」 | 外部／內部／網路已經在上方的列裡，展開區只留狀態與最後檢查 |
| 中繼節點的附註 | 「併進標題一行」 | 附註寫進標題，列表下那句說明拿掉；每列只寫「9 分前」、「路由」 |
| 穿透的說明 | 「改成只在滑過時顯示」 | 動作列下方那行常駐說明，改成游標停在或鍵盤焦點在「滑鼠穿透」上時才出現 |

之後擁有者對標題再問一次：

> ⇄ 中繼節點 2 · 僅從指令偵測，未驗證 像這裡的未驗證是否真的必須

### 協調者的解讀（不是擁有者的話）

- 拿掉「僅」與「未驗證」是協調者對上面那個問題的**解讀**，已照做：標題已經說了節點從哪來，列表不畫箭頭、不排成鏈、不標通道健康（UX-005），「未驗證」靠的是這些，不是一句話。標題定為「⇄ 中繼節點 {{count}} · 從指令偵測」（英文 "Relay nodes {{count}} · detected from commands"）。
- 兩處縮短是協調者自己加的，不是擁有者選的，擁有者可以退回：
  - 中繼節點讀取失敗、保留上次清單時的那一句：「無法更新中繼節點；以下 {{count}} 個是上次讀到的清單。」→「無法讀取，顯示上次讀到的 {{count}} 個」。只在 HUD 用新字串（`overlay.relayReadFailedStale`）；儀表板仍用原本的 `pivot.readFailedStale`。
  - 除此之外不縮短：未知 IP 的提示、標記表單、狀態句不動。

### 實作者的處理與未照做的部分

- **第一輪「拿掉重複三列」只拿掉了「外部」一列。** 協調者的指示是：若某列在某些狀態下帶著列上沒有的資訊，就先回報、不要拿掉。實作者量到兩列屬於這種情況：
  - 「內部」：列寬不足時內部 IP 會先被省略；暴露時展開區是強制打開的，正好是這一列唯一能看到完整內部 IP 的時候。列上的內部 IP 當時沒有 `title`。
  - 「網路」：讀不到網路類型時列上不顯示網路那一行（展開區寫「—」）；Wi-Fi 名稱長時列上會省略。
  兩列先留著，交給擁有者決定——結果見第 3 節的 D2。
- **更正（第一輪的說法偏樂觀）。** 第一輪回報「外部 IP 在每種量測組合下都完整顯示、內部欄先省略」。那組量測沒有包含「已暫停」（PAUSED）這個最長的錄製字樣。獨立審查從程式推算出：縮放 1.75、強調外部 IP、兩個 15 字元位址、英文 PAUSED／EXPOSED 時，外部欄會溢出到 ▼ ✕ 底下。實作者在測試頁重現：外部欄右緣比列的內容區多出 63px，落在按鈕上。原因是當時的寫法讓外部欄的收縮係數接近 0，內部欄縮到 0 之後，剩下的溢出沒有任何欄位吸收。修正見第 3 節。
- 讀取失敗、保留上次清單時，那一句移到中繼節點標題下方：新句子不再說「以下」，放在標題下才知道「無法讀取」指的是中繼節點。沒有清單時仍是原本那句「無法讀取中繼節點。這不代表沒有。」，單獨一行。兩種情況都有重試鈕。
- 「最後出現」留在每列時間的 `title`，並以只給輔助技術讀的文字讀出（第一輪用的 `aria-label` 不會被讀出，第二輪修正，見第 3 節）。
- 「保持展開」的兩個說明（`overlay.keepOpenOnHint`／`keepOpenOffHint`）原本就只在 `title`，沒有常駐顯示，不用改。
- 開啟穿透瞬間的 3 秒提示、`⌘⇧P` 與選單列／系統匣退出都沒有改。

## 3. 第二輪：寬度、鍵值表與審查修正

### 擁有者的話（逐項詢問，引號內是擁有者選的選項文字，選項由協調者寫）

| 項目 | 擁有者選的選項 | 內容 |
|---|---|---|
| D1 寬度與字級 | 「加寬到約 490，用原型字級」 | 視窗基準寬度由 440 改為約 490；列內用設計稿的字級：外部 IP 20px、其他 13px（縮放 1 時；小縮放仍守 11px 下限）；展開區 13px |
| D2 鍵值表 | 「兩列都拿掉，滑過看完整值」 | 內部、網路兩列也拿掉，展開區只剩狀態與最後檢查；列上的外部 IP、內部 IP、網路名稱一律帶 `title` 顯示完整值 |

### 實作者的做法

- 寬度：基準 490、強調外部 IP 再加 60（縮放 1）。原本 720 的上限從縮放 1.5 起就會截短，所以上限改成 963，正好等於縮放 1.75 加強調時公式算出的寬度，任何支援的設定都不會被上限截短。只有選了 1.75 的人會看到這麼寬的 HUD。收合列最低 42、視窗 60（`HUD_INITIAL_H` 由 58 改 60）。
- 列寬分配改用 flex 基準值，不再用收縮係數：外部欄要它的完整寬度（`0 1 auto`），內部欄只拿剩下的空間（`1 1 0`）。收縮係數會乘上基準寬度，只要外部欄有任何係數就會分到一點溢出，而一點就足以讓 IP 出現省略號。測試頁實測縮放 0.75–1.75 × 中英文 × 一般／暴露長位址／最壞（兩個 255.255.255.255 加 PAUSED）／強調／強調最壞，共 60 種組合：外部 IP 全部完整，沒有一種與 ▼ ✕ 重疊；省略的只有內部 IP 與網路名稱（滑過可看完整值）。另外把視窗強制縮到外部 IP 本身也放不下時，外部 IP 在列內省略，不會滑到按鈕底下。

### 審查發現，已修正

1. 外部 IP 溢出到 ▼ ✕ 底下（見上方更正）。
2. 滑過「滑鼠穿透」時說明會閃動：說明出現後、視窗還沒長高前，置中排版讓按鈕上移，游標可能離開按鈕。測試頁重現時，按鈕在那一刻由 218 移到 199。展開時改為貼齊頂端，位置與置中時靜止的位置相同；修正後按鈕停在原位，`overlay:autosize` 只有一次長高、一次縮回。
3. 穿透開啟時（主程序仍轉送滑鼠移動）不再顯示說明。
4. 滑過與聚焦分開記；展開區收合或穿透開啟時兩者都清掉。
5. 拿掉按鈕上與說明重複的 `title`；沒顯示說明時，以只給輔助技術的文字描述按鈕。
6. 「最後出現」改成只給輔助技術讀的文字（role-less `span` 上的 `aria-label` 不會被讀出），`title` 保留給游標。
7. e2e 以 `data-testid` 找鍵值表。
8. HUD 不載入 app 的樣式表，所以它的三個無限動畫原本不理會 `prefers-reduced-motion`；現在它自己的樣式區塊會在 reduce 時停掉動畫。
9. **這一項是協調者的決定，不是擁有者的**：暴露時的閃紅原本是發光的外框（亮度 1.5 倍），第一輪改成 1px 外框變色後明顯變弱。現在「顯示閃紅」開啟時，整個面板底色在 `#120a0b` 與 `#541d1e`（暗紅疊 28% 危險紅）之間閃動，外框與四角同步閃，仍不用光暈或模糊。擁有者可以調整幅度。
