# Implementation Plan: Settings Search, Type Names, Clock Meaning

## Canonical module interface

- `lib/settingsSearch.ts` `searchSettings(query, t)` over
  `lib/settingsSearchIndex.ts` (generated by `scripts/gen-settings-search.mjs`
  from `scripts/settings-search-sources.mjs`).
- `lib/timelineDomain.ts` `LANE_LABEL_KEYS`, `agentTypeLabel(type, t)` —
  the Timeline and the filter bar both read them.

## Constitution Check

- **Surface Truthfulness**: the search label is tied to a wired search; the
  clock states what it counts; types have names an operator uses.
- **Architectural Restraint**: no new settings pages or rearrangement; one
  shared name table instead of a second one.
- **Risk-Based Test-First**: copy-level changes, tested by render and source
  guards; the index guard prevents silent drift.

## Design

1. Index: per page, the i18n keys its source renders (toast/common excluded);
   `AgentsPanel.tsx` is split at `HookWatchPathsPanel`, which renders on Hooks.
2. Settings: results under the page list; choosing one switches page and
   scrolls the first element containing the text into view with a brief ring.
3. Filter bar and Timeline read `LANE_LABEL_KEYS`.
4. Status bar keeps its project-creation clock; adds tooltip and aria-label.
