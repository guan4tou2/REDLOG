# Feature Specification: 時間軸指令區間——每個終端機一條軌

**Feature Branch**: `feat/078-timeline-command-intervals-s1`（S0、S1）
**Created**: 2026-11-18
**Status**: Draft
**Input**: 設計原型 `02-timeline.html`（目標的圖，不是行為規格）；Spec 069 FR-008、FR-013；Spec 072「不在範圍」把「動作畫成區間」列為另案（`specs/072-event-kind-registry-and-readers/spec.md:332`）；Spec 074 FR-100–104 與 US3、FR-043、FR-049；`docs/UIUX-STANDARD.md` §6（控制密度，2026-11-14）、§26、§27；功能刪減審查 C.4。

> 本檔只寫可觀察的行為。模組邊界、函式簽名與切片在 plan.md。

## 問題（操作者的話）

標準時間軸今天是一列 44px 的灰點（`Timeline.tsx:75,727`）。哪一顆是哪個指令、誰跑的、跑多久、有沒有失敗，都要滑過或點開才知道。`command_start` 有載入，卻在配對後被摺掉（`Timeline.tsx:176-188`、`lib/timelineIncremental.ts:100-150`），所以「跑了四十分鐘的 nmap」和「一瞬間的 whoami」在圖上是同一顆點，位置還在結束的那一刻。兩個終端機同時在做事時，圖上分不出來。

### 本規格自行決定的（被否決的替代方案見 plan.md）

1. 只改標準模式。泳道模式照今天的畫法，維持完整清單（074 FR-104、根因審查 §4）。
2. 配對不另寫一套：用 `operationPairKey`，摺疊條件與今天 `collapseCommandPairs` 相同。沒有配對鍵的指令照舊是點。
3. 一個終端機一列（Q1）；事件列在最上面，收下所有不屬於任何區間的列。不建「來源不明」列。
4. 不加標籤欄（Q3）。軌道標籤是列內貼齊視窗左緣的小標籤，時間尺維持全出血（§27.3）。
5. 每條軌一條基線。重疊時後開始的畫在上面，不分層。
6. 沒看到結束的指令，虛線只畫到同軌下一個指令開始之處，是該軌最後一個時畫到軌道右緣；不畫結束記號（Q4）。
7. 選取的仍是事件列（`command_end`，沒有則 `command_start`）。Inspector、摘要列、卡片列不改。

## User Scenarios & Testing *(mandatory)*

| 故事 | 優先級 | 摘要 |
|---|---|---|
| US1 一眼讀出誰跑了什麼、多久、有沒有失敗 | P1 | 兩個終端機各自一列；指令是起點、線、終點；名稱印在線上方 |
| US2 沒看到的不畫成有 | P1 | 起點或終點不在已載入的列中時，那一端不畫成有；篩選不把跑完的指令變成還在跑 |
| US3 今天看得到的都還在 | P1 | 每一列恰好出現一次；沒有終端身分的專案與今天完全相同 |
| US4 鍵盤與讀屏走得到每段區間 | P2 | ←/→ 依時間、↑/↓ 換列；每段區間有完整的可及名稱 |

### User Story 1（P1）
**Independent Test**：兩個終端機各 6 個指令（含一個失敗、一個未結束），1280×800、縮放 100%。
1. **Given** 終端 A 有 `nmap -sV 10.0.0.5`，14:00:00 開始、14:00:42 以結束碼 0 結束，**Then** A 那一列在 14:00:00 有起點記號，線畫到 14:00:42，終點是實心短豎線，線上方印出指令文字。
2. **Given** 終端 B 的 `cat config.php` 以結束碼 1 結束，**Then** 終點是 ✕ 形並印出 `1`；黑白截圖下仍與成功的終點不同。
3. **Given** 終端 B 的 `nc -lvnp 4444` 只有 `command_start`，**Then** 畫成虛線、沒有終點記號，`title` 與可及名稱含「執行中／狀態未知」。

### User Story 2（P1）
1. **Given** 只載入最新 200 列，其中一個 `command_end` 的 `command_start` 在更早的頁，**Then** 畫終點記號與左側一小段固定長度的虛線；線不延伸到已載入範圍的左緣。載入更早的頁後，同一段區間改畫出完整的線。
2. **Given** 套用了時間範圍的結束時間，某指令的 `command_end` 在範圍之後，**Then** 該區間畫成起點加一小段虛線，不延伸到右緣。
3. **Given** 同一個配對鍵有兩筆內容不同的 `command_end`，**Then** 不畫區間，這些列各自是事件列上的點。

### User Story 3（P1）
1. **Given** 任意一組已載入的列，**Then** 標準模式下每一列恰好屬於一段區間或事件列上的一個記號（含叢集的成員）。
2. **Given** 專案中沒有帶配對鍵的指令，**Then** 畫面與本規格之前相同：一列、沒有終端列。

### Edge Cases
- 結束時間早於開始時間（來源時鐘）：在開始時間畫一個點狀記號，不畫負寬度的線；`title` 說明。
- 同一個鍵有多筆 `command_start`：最早的一筆是起點，其餘是成員，不另畫。
- 巢狀（`redlog-run` 會讓 preexec 與 wrapper 各送一對，`hooks/shell-common.sh:925-927`）：兩段區間重疊，後開始的在上面；起點在同一個 14px 格內時合成計數記號。
- 內建終端機的 `command_boundary`（`src/main/terminal-manager.ts:163-170`）：區間畫到該列的時間，終點是空心短豎線。
- 壓縮閒置（略過閒置）打開時，區間照 `toX` 橫跨間隙帶；間隙帶與它的時長標籤不變。

## Requirements *(mandatory)*

### Functional Requirements

#### A. 哪些列成為區間、如何配對
- **FR-001** 區間只在標準模式畫。泳道模式的資料、摺疊與畫法不變。
- **FR-002** 一列參與區間的條件：`agent_type` 為 `shell`、`subtype` 為 `command_start` 或 `command_end`，且 `operationPairKey` 有值。其他列（含沒有 `command_id` 或沒有終端身分的指令列）照今天畫成事件列上的點。PID 與指令文字不得代替配對鍵。
- **FR-003** 起訖成對的條件與今天的摺疊相同：同鍵、該鍵只有一種 `command_end` 內容、兩列的 `command` 文字相等。不成立時不畫區間，相關的列留在事件列。
- **FR-004** 區間的起點時間是起點列的 `timestamp`，終點時間是終點列的 `timestamp`。某一端的列不在本頁已載入的列中時，那一端是「未知」：不得以已載入範圍的邊緣、`duration_sec` 或任何其他時間代替它的位置。
- **FR-005** 結束依據為封閉列舉（074 FR-043 的子集）：
  - `observed`：有配對的 `command_end`。
  - `superseded`：有一筆 `command_boundary` 以 `_causes` 或「同終端 + 同 `command_id`」指向它，或同一終端在它開始之後有 `session_end`。
  - `open`：以上皆無。
- **FR-006** 起點未知的區間：畫終點記號與左側固定 16px 的虛線。終點為 `open` 的區間：見 FR-024。兩者都不得畫成完整的線。
- **FR-007** 完整性：標準模式下，每一個今天會畫出的列恰好出現一次——是某段區間的成員，或是事件列上某個記號的成員。
- **FR-008** `endTs < startTs` 的區間標為時序異常：畫成起點時間上的點狀記號，`title` 與可及名稱說明「結束時間早於開始時間」。

#### B. 軌道與列
- **FR-010** 軌道是終端身分：取列的 `_ingest.terminal`；沒有時取 `data.terminalId`，再取 `data.terminal_id`。hook 的列與內建終端機的列用同一條規則。規則與核心的 `rowTerminal`（`src/core/ingest/terminal.ts`）相同，包括：蓋章的入口是 `api` 或 `handoff` 而沒有記下終端時，該列沒有終端身分。renderer 不 import 該檔（它 import `node:crypto`），以測試鎖住兩者一致。
- **FR-011** 列的順序：第 0 列是事件列（今天的標準列，扣掉已成為區間成員的列），其後每個「在已載入的列中至少有一段區間」的終端機各一列。
- **FR-012** 終端列的順序在終端機的集合改變時（出現新的終端機、換篩選）依最後活動時間由新到舊重排；集合不變時順序不動。兩個終端機交替下指令不得讓列互換位置。
- **FR-013**（Q1）不捲動時最多顯示事件列加 3 個終端列；更多的終端列以垂直捲動到達。不依視窗高度或寬度隱藏任何列（§6 控制密度）。
- **FR-014**（Q2、Q3）每個終端列有一個不可互動的標籤，貼齊可視範圍左緣、位於名稱區（線的上方），不遮線與記號：
  - 內建終端機：沿用「終端 {{id}}」，`id` 為身分的前 4 個字元，與 session 帶的標籤同字。
  - 其他：`{shell} {pid}`（例如 `zsh 4821`）；缺 `pid` 時為身分的末 6 個字元。不用 tty：列上沒有這個欄位。
  - 完整身分在該列的可及名稱。
- **FR-015** 沒有終端身分的指令留在事件列。不建「來源不明」列。
- **FR-016** 已載入的列中沒有任何區間時，不出現終端列，版面與本規格之前相同。

#### C. 區間的組成與狀態
- **FR-020** 一段區間由起點記號（實心圓，8px）、線（2px）、終點記號組成，畫在該列的同一條基線上。
- **FR-021** 狀態與形狀（黑白截圖下兩兩可分）：

  | 狀態 | 條件 | 線 | 終點 |
  |---|---|---|---|
  | 成功 | `observed`，結束碼 0 | 實線 | 實心短豎線 |
  | 失敗 | `observed`，結束碼為非 0 的數值 | 實線 | ✕ 形，其後印結束碼 |
  | 已結束、沒有結果 | `observed` 但沒有數值結束碼；或 `superseded` | 實線 | 空心短豎線 |
  | 執行中／狀態未知 | `open` | 虛線 | 無 |

- **FR-022** 失敗不得只靠顏色：✕ 形一定畫。結束碼在右側有 20px 以上空間時印在圖上，並一定出現在 `title` 與可及名稱。
- **FR-023** 「已結束、沒有結果」的 `title`：沒有結束碼時用「已結束 · 未記錄結束碼」（既有鍵 `activity.result.ended`）；`superseded` 時用既有的 `eventTitle.commandInterrupted`。
- **FR-024**（Q4）`open` 的虛線畫到同一軌下一段區間的起點；它是該軌最後一段時畫到軌道右緣。任何情況都不畫終點記號，`title` 用「執行中／狀態未知」（`timeline.command.unfinished`）。
- **FR-025** 本頁的讀取可能缺少結束列時，`open` 區間只畫起點記號與 16px 虛線，不延伸。條件為：共用篩選帶有目標、只看範圍內、隱藏個人流量或結束時間任一項，或即時列的接收失敗尚未重試成功（`timeline-live-failed` 顯示中）。
- **FR-026** 畫出的寬度小於 14px 的區間畫成點狀記號：起點記號加上狀態的形狀（失敗為 ✕ 與結束碼，沒有結果為空心圓，未知為 16px 虛線）。不得小於 8px，不得因為太短而不畫。
- **FR-027** 今天畫在 `command_end` 點上的資訊留在終點記號上：輸出是否已記錄的小點（`ioMark`）、該列的徽章（`badgesById` 的第一個）。

#### D. 名稱
- **FR-030** 印在圖上的文字是指令本身（起點列的 `command`，沒有起點列時取終點列），空白與換行壓成單一空白，經 `safeDisplay`（`lib/evidenceText.ts:31`）。不加前綴、不加推論。
- **FR-031** 名稱印在線的上方、從起點向右。到同一列下一個記號之間的空間不足 48px 而左側較寬時，改放在起點左側、靠右對齊。兩側都不足 48px 時不印。
- **FR-032** 名稱以省略號截斷到可用寬度，上限 320px；不換行、不壓過鄰近的記號或名稱。
- **FR-033** 每段區間的 `title` 為「開始時間–結束時間 · 軌道標籤 · 完整指令 · 耗時 · 狀態」。耗時取兩列 `timestamp` 之差；起點未知時取終點列的 `duration_sec` 並標明「來源回報」。`title` 不得與旁邊印出的名稱逐字相同（`test/ui-copy.test.ts`）。
- **FR-034** 計數記號不印名稱。

#### E. 密度
- **FR-040** 同一列中，起點落在同一個 14px 格的區間合成一個計數記號，數字是指令數。其成員的聯集範圍達 14px 時，記號右側畫出涵蓋該範圍的線。
- **FR-041** 計數記號含失敗的成員時帶 ✕ 形；含未知的成員時邊框為虛線。可及名稱分別說出指令數、失敗數、未知數。
- **FR-042** 同一列任一位置最多兩段區間重疊；第三段併入最近開始的那一段，成為計數記號。
- **FR-043** 沒有「到某個縮放才出現名稱」的全域門檻：名稱是否印出只由 FR-031 的可用寬度決定。
- **FR-044** 事件列的叢集規則、數字與彈出清單不變（`buildClusters`）；它的數字是該列上的事件列數。終端列的數字是指令數。兩者的可及名稱各自寫明單位。
- **FR-045** 點計數記號開啟今天的叢集清單（上限 50 筆，超過顯示「還有 N 個」）；清單的項目是各指令的選取列。

#### F. 選取、鍵盤、焦點、點擊目標
- **FR-050** 選取一段區間等於選取它的選取列：`command_end`，沒有則 `command_start`。選取的列是區間的任何成員時（例如從搜尋開啟的是 `command_start`），該區間顯示為選取。
- **FR-051** 單擊選取並顯示摘要列，再單擊同一段取消；雙擊開啟詳情；聚焦時 Enter 開關詳情。平移結束時的放開不算點擊。
- **FR-052** 選取外觀照 §6：整段區間外圍 2px 品牌紅外環，起點記號 1.3 倍。
- **FR-053** ←/→ 依時間走過所有列上的事件與區間，區間的位置是其選取列的顯示時間（與今天相同）。⌥←/→ 留在同一列。↑/↓ 換到相鄰的列，落在時間最接近的一筆。⇧←/→、Home/End 不變。
- **FR-054** 走到畫面外或捲出可視列的區間時，水平與垂直都捲入視野，不改變縮放。
- **FR-055** 每段區間與每個計數記號的點擊區域寬高都不小於 27 CSS px；與相鄰的計數記號相接於中點。兩段各自獨立的區間重疊時，後開始的在上。
- **FR-056** 整個軌道區只有一個 Tab 停留點：選取的那一筆；沒有選取時是 DOM 順序中的第一筆。
- **FR-057** 在區間上雙擊或按右鍵不觸發空白處的「前後 5 分鐘」縮放與「在此放標記」選單。

#### G. 與既有疊層共存
- **FR-060** 暫停帶、終端 session 帶、壓縮間隙帶、現在線、斷鏈之後的紅色區段照今天畫在所有列上（高度隨列數），區間畫在它們上面。
- **FR-061** `/` 篩選框與焦點鏈的變暗：區間的任一成員列被點亮時該區間不變暗。變暗的區間不可點，`aria-disabled`，可及名稱附「不符合」。
- **FR-062** 隱藏泳道是泳道模式的控制，標準模式的終端列不受它影響。
- **FR-063** 歸因警示、即時／回到最新、時間尺的〔焦點〕〔最新〕記號不變。〔焦點〕標在選取列的時間。
- **FR-064** 密度條不變：它數的是事件列，不畫區間；「未載入」段的條件與文字不變。
- **FR-065** 區間的起點時間計入時間範圍：畫出的區間其起點不得落在軌道之外。

#### H. 誠實規則
- **FR-070** 部分載入（`hasMore`）時，終端列的指令數在可及名稱中以「至少」的寫法呈現（沿用泳道的 `+` 寫法）。
- **FR-071** 讀取失敗（`timeline-page-failed`、`timeline-live-failed`）時，已畫出的區間不因此改變狀態；缺少的那一端依 FR-006、FR-025 處理。
- **FR-072** 任何篩選都不得讓一段區間顯示為成功、失敗或已結束，除非它的結束列在本頁已載入的列中。
- **FR-073** 所有印出的時刻經 `lib/time` 的格式化函式（顯示時區）；耗時是經過的時間，不受時區影響。
- **FR-074** 區間、記號與名稱沒有動畫；未結束的區間不閃爍、不流動。變暗的 120ms 透明度轉場受 `prefers-reduced-motion` 的全域規則約束（`styles/index.css:365`）。

#### I. 效能
- **FR-080** 由列建立區間：每一列走訪一次。即時批次中沒有指令列時沿用上一次的結果，不重算。
- **FR-081** 版面在時間對應或縮放改變時重算，每段區間走訪一次；捲動的每一格只做範圍篩選，不重算版面。
- **FR-082** 畫出的區間記號數有上限：每列不超過 ⌈3W／14⌉ + 2（W 為可視寬度），且只有可視的列與上下各一列有內容。
- **FR-083** 20 萬列、2 萬個指令的專案：建立與版面的工作量與列數成正比（比值 < 1.5，仿 074 FR-094 的工作量計數）。牆鐘只在 `REDLOG_PERF=1` 量。

#### J. 無障礙
- **FR-090** 每個終端列是一個群組，可及名稱為「終端機 {標籤}，{N} 個指令」加上完整身分。
- **FR-091** 每段區間是按鈕，可及名稱為「{開始時間}–{結束時間} {軌道標籤} · {完整指令} · 耗時 · 狀態」。狀態一定以文字出現（結束碼 0／失敗 N／已結束、未記錄結束碼／執行中／狀態未知／開始不在已載入範圍）。選取時 `aria-pressed`。
- **FR-092** 計數記號的可及名稱：「{N} 個指令 · {起}–{迄} · 失敗 {k} · 狀態未知 {m}」。

### Key Entities
- **指令區間**：一對（或半對）`command_start`／`command_end` 在圖上的呈現；有起訖時間（任一端可為未知）、結束依據、指令文字、結束碼。
- **終端軌**：一個終端身分的所有指令區間。
- **選取列**：選取一段區間時實際被選取的事件列。
- **事件列**：標準模式的第 0 列；所有不是區間成員的列。

## Success Criteria *(mandatory)*
- **SC-001** 性質測試（10,000 組隨機列，含亂序、重複、衝突、缺半）：FR-007 的分割成立；被摺疊的 `command_start` 集合等於兩端俱全的區間的起點集合；`open` 區間的起點集合等於 `unfinishedCommandIds` 扣掉被取代的。
- **SC-002** 增量等價：`extend(build(前綴), 全部)` 不是 null 就等於 `build(全部)`（併入 `test/timeline-incremental-equivalence.test.ts`）。

## Assumptions
- 單一使用者、單機。
- 本頁載入的是由最新往回的一段連續範圍（`hooks/useTimelinePages.ts`），所以「起點已載入而終點沒有」只可能是：還沒結束、沒被記到，或被篩選排除。
- 三個 shell hook 的指令列都帶 `shell`、`terminalId`、`command_id`。
- 一個終端機同一時間通常只有一個前景指令；重疊是例外。

## 不在範圍（另案；本規格不得順手做）
- 移除卡片列、圖例或標準／泳道模式；合併三個時間範圍預設；以時長取代縮放百分比；移除即時控制；把時間尺移到圖的下方。
- 狀態帶（出口、通道、目標、記錄）：需要 074 的 `intervals`。
- 掛在動作上的結果數（`+4,614`）與註記數：需要 074 的 `cause_counts`。
- 「來源不明」列。
- AI「輪」的區間：輪今天不是投影中的身分。
- 把終端 session 帶收進各自的終端列；在密度條上畫區間；同時存活的終端機共用列。
- `command_output` 併入所屬的區間（今天是事件列上的點，維持）。
- `carriesState`／`neverFold` 讀錯欄位（`exitCode` 對 `exit_code`）的修正：另開 PR。

## 遷移註記（Spec 074 FR-100 落地時）
- **接縫**：`lib/timelineIntervals.ts` 的 `buildCommandIntervals(rows): TimelineIntervalSet`。074 以「讀 `intervals` 投影並轉成同一個 `TimelineIntervalSet`」取代它。`TimelineIntervalSet` 是純資料（列 id、時間、結束依據、指令文字、結束碼），不含事件物件；版面與繪製不需要改。

  - 選取列可能不在已載入的列中，要以 id 取回（今天的 `resolveReferencedEvent`）。
  - FR-025 的條件改由投影的完整度回答。
  - 標準模式不再需要摺疊起點（074 FR-100）。
