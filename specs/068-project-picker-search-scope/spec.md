# Feature Specification: 專案選擇畫面 — 搜尋與範圍狀態徽章

**Feature Branch**: `feat/project-picker-search-scope-badge`
**Created**: 2026-11-05
**Status**: Draft
**Input**: 2026-11-05 提供的專案啟動介面設計稿與 `ProjectPicker.tsx`／`project-manager.ts`／`config.ts` 現況審查(見 implementation-notes.md)。

## 決策與範圍

設計稿裡值得採用的只有兩件事:**在專案清單上找專案**,以及**在列上看出這個專案有沒有宣告範圍**。建立流程不動——範圍仍由 Settings ▸ Scope 持有(#297)。

兩件事都不新增能力,只是讓既有資料讀得到:

1. 搜尋是對已載入清單的前端篩選,不新增 IPC。
2. 範圍徽章需要一個新的唯讀查詢,因為清單目前沒有範圍欄位。**這個查詢必須能說「不知道」**,否則一個損毀的 `config.yaml` 會被顯示成「未設定範圍」(見 implementation-notes 陷阱 1、2)。

### 已決議(2026-11-05,D1–D4 全部採用)

| # | 決策 | 定案與驗收重點 |
| --- | --- | --- |
| D1 | 搜尋框顯示 | 以**篩選前的專案總數**為準,≥ 6 才顯示。5 個隱藏、6 個顯示。輸入後即使只剩 1 筆或 0 筆,搜尋框仍保留且保有焦點,使用者可繼續輸入或清除。 |
| D2 | 範圍徽章 | 已設定顯示中性的「N 個目標」;確認為空顯示「未設定範圍」;無法可靠判定顯示「範圍未知」。計數沿用實際生效的範圍語意(`scope.targets` 與 Burp／ZAP 範圍檔合併)。**任何一個已宣告的範圍檔讀取失敗,整體顯示「範圍未知」**,不把部分數量當成總數。 |
| D3 | 搜尋框內 Enter | 只有在**非空白查詢**且**恰好符合 1 個**專案時才開啟該專案。0 筆或多筆時保留查詢與焦點,不移動焦點。使用中文輸入法時,按 Enter 確認組字不得觸發開啟。 |
| D4 | 徽章查詢 | 獨立唯讀查詢。清單先顯示並可操作,再依穩定的專案識別回填徽章。載入中留白;讀取失敗才顯示「範圍未知」。單一專案失敗不影響其他列;搜尋或重新整理後晚回來的結果不得貼到另一個專案。 |

## User Scenarios & Testing *(mandatory)*

| 故事 | 優先級 | 說明 |
| --- | --- | --- |
| US1 在清單上用名稱找專案 | P1 | 前端篩選,不動資料層 |
| US2 在清單上看出哪個專案還沒宣告範圍 | P1 | 新的唯讀範圍摘要,三態 |

### User Story 1 — 搜尋(P1)

專案多了之後,操作者輸入名稱片段就能把清單縮到符合者;清空即回到完整清單。篩選不改變排序、不影響改名／刪除／開啟。

### User Story 2 — 範圍狀態(P1)

操作者在清單上就能看出每個專案是「N 個目標」、「未設定範圍」,或「範圍未知」,不必逐一開啟專案。「未設定範圍」是提示而不是警報——剛建立的專案本來就還沒有範圍。

### Edge Cases

- 篩選結果為 0:顯示「沒有符合『…』的專案」與清除篩選,**與「還沒有任何專案」的空狀態不同文案**。
- 清單載入失敗:沿用既有失敗狀態,不顯示搜尋框(沒有可搜尋的資料)。
- 篩選中刪除了最後一個符合的專案:回到「沒有符合」狀態,不自動清掉搜尋字串。
- 篩選中改名使其不再符合:該列留到提交完成再消失,不在輸入途中跳走。
- 同名專案(已有的「同名多顯示建立日期」)篩選後仍保持區分。
- 範圍摘要查詢整體失敗:清單照常,每列顯示「範圍未知」(不是「未設定範圍」)。
- 查詢尚未回來:徽章位置留白,不顯示「未設定範圍」作為預設。
- 專案宣告了兩個範圍檔、其中一個讀取失敗:整體「範圍未知」,不顯示另一個檔的數量。
- 搜尋框輸入為空白(只有空格)按 Enter:不開啟任何專案。
- 查詢尚在途中時使用者篩選、改名或刪除專案:回來的結果依專案 id 套用,已不存在的 id 丟棄。
- 單一專案的 `config.yaml` 損毀:只有那一列顯示「範圍未知」。
- 專案只用 scope 檔(Burp／ZAP)宣告範圍:計入條目數,不判為未設定。
- scope 檔讀不到或格式無效:該列「範圍未知」,不是「未設定範圍」。
- 專案目錄剛建立、`config.yaml` 尚不存在:「未設定範圍」(合法的新專案)。

## Requirements *(mandatory)*

### Functional Requirements

#### 搜尋(US1)

- **FR-001** (D1′)清單上方一律顯示搜尋框;搜尋時顯示「符合數／總數」。搜尋框一旦顯示,不因篩選結果變成 0 或 1 筆而卸載或失去焦點。
- **FR-002** 以名稱做不分大小寫、以空白分詞的 AND 比對;沿用現有共用的比對函式,不複製第三份。篩選只影響顯示,不改變資料、排序或選取行為。
- **FR-003** 篩選結果為 0 與清單為空是兩個不同狀態,各有自己的文案;前者提供「清除篩選」。
- **FR-004** 搜尋框內的方向鍵與輸入不得觸發列表開啟或導覽。(D3′)Enter 開啟選取中的那一列;0 筆時保留查詢與焦點。輸入法組字中(`isComposing` 或 keyCode 229)的 Enter 一律不觸發開啟。既有的鍵盤開啟、建立欄位焦點行為不退化。
- **FR-005** 搜尋框有可存取名稱;篩選結果數變化以 `role="status"` 告知。

#### 範圍狀態(US2)

- **FR-010** 新增唯讀查詢,對清單中每個專案回傳範圍摘要,三態:`{ state: 'set', count }`、`{ state: 'unset' }`、`{ state: 'unknown', reason }`。`count` 為實際生效的範圍(`scope.targets` 與 scope 檔條目合併去重)。
- **FR-011** `unknown` 的條件:`config.yaml` 存在但無法讀取或解析;**任何**已宣告的 scope 檔 `unreadable`／`invalid`(整體為 `unknown`,不回報部分數量)。`config.yaml` 不存在視為 `unset`。**不得**透過會吞錯誤的 `loadConfig` 取得此判斷。
- **FR-012** 該查詢不寫入任何檔案、不改變 `lastOpened`、不開啟專案資料庫。
- **FR-013** 單一專案的失敗只影響那一列。查詢整體失敗時,清單照常顯示且可操作,每一列顯示「範圍未知」(**不是**「未設定範圍」,也不是空白);載入中則留白。
- **FR-014** 徽章語氣沿用 `scopeIssue`:`set` 為中性「N 個目標」;`unset` 顯示「未設定範圍」,是提示層級(不使用警報色、不使用「警告」字樣);`unknown` 顯示中性的「範圍未知」,可帶原因於 `title`。
- **FR-015** 徽章文案走 i18n(en／zh-TW),計數使用單複數安全的寫法,不寫死「規則」字樣(範圍條目是目標,不是規則)。
- **FR-016** 範圍摘要不改變 `ProjectMeta` 的既有欄位,也不改 `project:list` 的回傳形狀。
- **FR-017** 徽章以穩定的專案 id 回填,不以列的位置或篩選後的索引對應。每次進入選擇畫面或重新整理為一個新的查詢世代;舊世代晚回來的結果丟棄,不得貼到另一個專案(包含篩選、改名、刪除之後)。
- **FR-018** 徽章查詢不得延後清單的首次顯示或其可操作性。

### Key Entities

- **範圍摘要**:`{ projectId, state: 'set' | 'unset' | 'unknown', count?, reason? }`,每次進入選擇畫面讀取一次,僅供顯示。
- **清單篩選**:元件內的字串狀態,不持久化。

## Success Criteria *(mandatory)*

- 10 個以上專案時,輸入名稱片段能在不捲動的情況下找到目標;清空後完整清單回復。
- 一個 `config.yaml` 損毀的專案顯示「範圍未知」,**不是**「未設定範圍」;只用 scope 檔宣告範圍的專案不被標成未設定;宣告的範圍檔有任何一個讀不到,整體為「範圍未知」。
- 範圍摘要讀取失敗時,清單的載入、開啟、改名、刪除都不受影響,各列顯示「範圍未知」。
- 清單首次顯示的等待時間不因範圍摘要增加(徽章晚於清單出現是可接受的)。
- 任何專案數都顯示搜尋框;在搜尋框輸入使結果為 0 或 1 筆時,搜尋框仍有焦點。
- Enter 開啟選取中的列(預設第一個符合項);0 筆、輸入法組字中的 Enter 不開啟。
- 既有的專案清單 e2e、鍵盤開啟、載入／空／失敗狀態回歸全綠;五道 push gate 通過。

## Assumptions

- 專案數量為數十個以內;不做分頁或虛擬捲動。
- 範圍摘要在進入選擇畫面(或重新整理)時讀取一次,不輪詢;使用者在別處改了範圍,下次進入畫面才會更新。
- 不改建立流程、不新增「開啟本機專案」入口(與本規格無關)。
- 驗收在 macOS 原生 Electron;Windows 路徑與檔案鎖行為以單元測試涵蓋。
