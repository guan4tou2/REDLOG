# Feature Specification: 紀錄優先的工作區與操作流程

**Feature Branch**: `codex/first-use-recording-guidance`（隔離候選；擷取基礎與配對修正進行中，主導覽尚未替換）。
**Created**: 2026-10-26
**Status**: Draft
**Input**: 使用者提供的全產品審查、Activity Log／搜尋／I/O／AI 閱讀與設定整併建議，及本次補齊八項跨層契約與需求追溯的審查。

## 決策與範圍

RedLog 是本機紅隊／滲透操作紀錄工具。優先順序為：**可靠保存 → 容易接入 → 找回與交付 → 操作效率 → 視覺精修**。日常使用者在接入後應能專心操作原本的工具，不須逐條管理 RedLog。

三個使用階段：接入、背景記錄、查找與交付。沿用既有擷取、查詢、錄影、外掛及凍結匯出契約；本規格整理操作入口和閱讀方式，不重寫擷取系統。

目標導覽為 **總覽、活動紀錄、HTTP 紀錄、目標、證據與註記**，另保留選用 Terminal 與固定 Settings。頁數是設計目標，不是完成標準；缺少功能不得以刪入口掩蓋。活動紀錄內有活動列表、輸入／輸出、AI 對話三種閱讀方式，Session 是篩選與上下文，不新增 AI 聊天產品。

AI 僅 Claude Code、Codex，依此順序；離線可選套件預設未安裝、未授權。不得重新提供 OpenCode 官方安裝或擷取入口，歷史資料仍可用通用檢視及匯出。

規格的操作契約在 [ux-contract.md](ux-contract.md)，驗收在 [acceptance.md](acceptance.md)。[implementation-notes.md](implementation-notes.md) 記錄現況、既有能力、依賴與分批界線；不把建議當成已實作。

新增的跨層契約依序為 [C1 Activity／工具分類](contracts/activity-projection.md)、[C2 搜尋覆蓋](contracts/search-coverage.md)、[C3 Content Viewer](contracts/content-viewer.md)、[C4 證據錨點](contracts/evidence-anchor.md)、[C5 匯出快照](contracts/export-snapshot.md)、[C6 擷取邊界／Terminal App](contracts/capture-boundaries.md)。[需求追溯表](traceability.md) 將全部 FR 對應既有元件／資料契約、驗收案例及交付階段；[契約案例](contract-acceptance.md) 全為 NOT RUN。

新增契約細化原有需求，不重編 FR-001–045，也不聲稱 API、索引或可信 Terminal App 辨識已完成。

四階段 gate 見 [實作切分](implementation-notes.md#5-四階段交付與退場-gate)；優先級不是允許跳過前置契約的許可。

### User Story 1 — 第一次就能開始記自己的終端（Priority: P0）

新使用者建立專案，選擇正在使用的終端環境，完成一次接入，確認指令、輸出與結束碼確實保存。HTTP(S) 與選用來源可稍後設定。

**Why this priority**: 未取得第一筆可讀證據，其他工作區沒有實際價值。
**Independent Test**: 在乾淨安裝環境，從啟動到第一筆指令／輸出／非零結束碼，再重啟讀回。

**Acceptance Scenarios**:
1. **Given** 新專案無來源，**When** 使用者開始終端接入，**Then** 自動辨識適用的 Bash／Zsh／PowerShell，允許手動選擇；不列出此平台無法執行的安裝操作。
2. **Given** 使用者只需記終端，**When** Shell 驗證完成，**Then** 可以開始工作，不因未設定 HTTPS、Scope 或 AI 被擋住；未驗證來源仍如實標示。
3. **Given** 接入失敗，**When** 查看狀態，**Then** 能辨識原因及未保存的內容，直接修復或重試；不重跑原本的測試命令。
4. **Given** 同時使用 Warp 與其他 Terminal App，**When** 設為只記 Warp，**Then** 選擇的作用範圍清楚，其他 App 不因安裝同一 Shell 接入而被記錄。
5. **Given** 略過首次引導，**When** 稍後從總覽的來源狀態進入，**Then** 直達該來源的接入／驗證設定，不重走整場首次引導。

### User Story 2 — 不打斷操作地記錄，知道缺口在哪（Priority: P0）

操作員正常使用多個終端、瀏覽器及已授權的工具。RedLog 不要求逐道切模式，不以安靜冒充故障，也不以程序啟動冒充已保存。

**Why this priority**: 降低日常摩擦必須以證據可信及隱私為前提。
**Independent Test**: 三個終端、一個長工作階段，包含暫停、背景輸出、來源中斷、重啟與切換專案。

**Acceptance Scenarios**:
1. **Given** 已接入來源，**When** 進行支援範圍內的一般操作，**Then** 不需額外按記錄／儲存；未支援的互動擷取不假裝完整。
2. **Given** HTTP 代理已啟動，**When** 尚未證實此用戶端能解密 HTTPS，**Then** 不顯示 HTTPS 已驗證；HTTP 與 HTTPS 使用同一網頁入口及 Scope。
3. **Given** 來源暫時沒有新資料，**When** 檢視來源，**Then** 顯示最近活動資訊，不僅因閒置就判故障。
4. **Given** 暫停、容量不足或連線失敗，**When** 恢復操作，**Then** 已保存內容與缺口仍可查；不得在恢復後偷偷保存暫停區間的新原文。
5. **Given** 長命令跨專案，**When** 切換專案或重啟，**Then** 顯示實際錄製歸屬與中斷；原專案內容不出現在另一專案，還原閱讀不等於恢復原程序。

### User Story 3 — 從同一工作區找回操作與完整輸出（Priority: P1）

使用者以關鍵字、時間、目標或 Session 找回活動，點開就能閱讀實際保存的指令、輸出及附件；不必在多個查詢頁重新找一次。

**Why this priority**: 找得到事件但讀不到輸出，不足以支援調查及交付。
**Independent Test**: 已知關鍵字只存在未載入頁、被折疊結果、長輸出附件及錄影片段；逐項找回。

**Acceptance Scenarios**:
1. **Given** 多頁紀錄，**When** 搜尋關鍵字並套用條件，**Then** 對整個專案的支援資料求值，不只篩目前畫面；分頁、數量與匯出使用相同條件。
2. **Given** 命中折疊的 Tool Result 或背景輸出，**When** 打開結果，**Then** 顯示對應操作、自動展開命中內容並定位原文；原始命中與操作群組數分開。
3. **Given** 輸出已保存但預覽有限，**When** 開完整檢視，**Then** 能繼續讀取、內容搜尋、複製或取出原始證據；不是只顯示「已保存」。
4. **Given** 只有分離的 stdout／stderr，**When** 檢視輸出，**Then** 不編造原始交錯順序；PTY 合併畫面也不偽裝為可分離的兩路輸出。
5. **Given** 目前條件不支援錄影索引搜尋，**When** 沒有命中，**Then** 明示受限範圍，不混入未套用條件的錄影結果，也不宣稱全專案沒有證據。
6. **Given** 正在閱讀舊資料，**When** 新事件或結果到達，**Then** 保持閱讀錨點與選取，只有主動跟隨最新時才自動移動。

### User Story 4 — 連續閱讀 AI 對話，核對工具回報（Priority: P1）

使用者在活動紀錄內選 Claude Code 或 Codex 的 Session，連續閱讀 Prompt、回答、工具輸入及結果，同時辨別 AI 回報和獨立觀測。

**Why this priority**: 來源混在同一資料集中，不表示證據性質相同。
**Independent Test**: 兩個提供者、多個 Session，同名指令、結果晚到、結果缺少及獨立 Shell 觀測並存。

**Acceptance Scenarios**:
1. **Given** 已保存 AI Session，**When** 選擇「指令＋Claude Code」，**Then** 找到明確的 Shell 執行工具回報，不混入一般回答，也不推定 Shell 已獨立觀測。
2. **Given** 工具結果晚到或缺少，**When** 更新畫面，**Then** 維持同一操作及位置；顯示實際配對狀態，不把無結果直接判為失敗或執行中。
3. **Given** AI 與 Shell 指令文字相同且時間接近，**When** 閱讀群組，**Then** 無可信關聯就分開，時間鄰近僅能作相關背景。
4. **Given** 對話長文，**When** 側欄切成全寬或換閱讀模式，**Then** 保留同一訊息、搜尋及閱讀位置；不再新增獨立 AI 主頁。
5. **Given** Thinking 未提供或只保存預覽，**When** 使用者展開，**Then** 如實呈現可用程度；「不顯示」不冒充「未保存原文」。

### User Story 5 — 一個來源入口完成設定與修復（Priority: P2）

使用者以工作目的找設定，不需要理解外掛、Adapter 或 Pack；安裝範圍與專案授權仍清楚分開。

**Why this priority**: 設定資訊架構整理排在可靠擷取之後；既有來源授權、保存失敗及可用修復入口仍屬第一階段，不因本故事 P2 而延後。
**Independent Test**: 從總覽進入失敗來源，原地修復；安裝 Claude Code 整合，授權一個目錄，排除一個 Session。

**Acceptance Scenarios**:
1. **Given** 官方 AI 整合未安裝，**When** 安裝，**Then** 只安裝 RedLog 擷取整合；不安裝 AI 工具、不自動授權對話，也不讀取所有家目錄 Session。
2. **Given** 已安裝但未授權，**When** 選擇本專案工作目錄並啟用，**Then** 僅從明確啟用邊界擷取；改目錄須重新確認，Session 排除只能縮小範圍。
3. **Given** 同一整合也列於進階外掛管理，**When** 查看該列，**Then** 不提供另一個互相抵觸的開關，而是直達唯一來源設定。
4. **Given** 安裝／啟停／儲存失敗，**When** 重試或切頁，**Then** 保留可恢復輸入、明示真實結果，不把 pending、失敗及成功混在一起。
5. **Given** 外部 Producer 必須自行啟動，**When** 開啟設定，**Then** 只呈現它真正支援的操作；不以假開關宣稱已在擷取。

### User Story 6 — 從目標與證據返回原始操作並交付（Priority: P1）

使用者從目標、HTTP、截圖、附件或註記找到來源，保留上下文，匯出實際選定資料與證據。

**Why this priority**: 主選單整併不能犧牲報告取材或交付正確性。
**Independent Test**: 找一筆掃描輸出、其 HTTP 交換及截圖，建立標記，選附件匯出，再讀回成品。

**Acceptance Scenarios**:
1. **Given** 目標頁包含不同類型事件，**When** 查看數量與 Scope，**Then** 計數單位正確；未設定、未知、沒有已觀測違規及讀取失敗分開，Scope 編輯回既有設定。
2. **Given** 檔案變更通知或候選截圖關聯，**When** 查看證據，**Then** 不冒充已保存檔案版本或已確認因果。
3. **Given** 選取一段輸出，**When** 建立正式標記，**Then** 保留來源與可用位置；私人書籤仍可編修，不冒充上鏈證據。
4. **Given** 折疊／展開群組或切閱讀模式，**When** 匯出同一已確認範圍，**Then** 不偷偷改變原始事件或附件集合。
5. **Given** 選目前查詢、某個操作或整個 Session，**When** 預覽匯出，**Then** 範圍明確且相互區分；摘要不冒充完整原始交付，預覽與成品一致。
6. **Given** 網頁 Scope 未設定，**When** 匯出網頁流量，**Then** 明示未依 Scope 篩選，可確認繼續或補設定；網頁規則不自動丟棄指令／輸出。

### User Story 7 — 小視窗與熟練操作仍然直接（Priority: P2）

使用者可用鍵盤、窄視窗與高縮放閱讀及交付；HUD 保留獨立的 IP 功能。

**Why this priority**: 精簡導覽必須增加操作效率，不能只改善截圖。
**Independent Test**: 同一任務用鍵盤及最小支援視窗完成，測長中文、長路徑、載入與失敗。

**Acceptance Scenarios**:
1. **Given** 窄視窗或高縮放，**When** 開詳情、來源設定及匯出，**Then** 主要動作可達；詳情切單欄保留返回，長內容只在自己的閱讀區捲動。
2. **Given** 只有 HUD／IP 需求且未開專案，**When** 啟動 HUD，**Then** 不強迫完成接入引導，也不冒充正在記錄專案。
3. **Given** 使用者熟悉鍵盤，**When** 切換新工作區，**Then** 畫面、指令面板與捷徑指向一致；不偷偷啟用選用來源。
4. **Given** 未受信任的輸出、Markdown 或連結，**When** 開啟證據，**Then** 不執行內容、不自動操作剪貼簿或載入外部內容。

### 補充契約驗收情境

1. **Given** Tool Result 先到或重送且翻頁後才見 Call，**When** 重建投影及開原深連結，**Then** 相同可靠來源鍵仍是同一 Activity；衝突與缺可靠鍵保留可追溯的原始 Event，不猜配對。
2. **Given** 關鍵字只在未索引的 stdout／cast 尾端，**When** 全域搜尋無命中，**Then** 回報該類覆蓋限制；能讀原件不冒充已全文索引。
3. **Given** 預覽後有新 Result、檔案追加或同大小改寫，**When** 執行匯出，**Then** 只交付已確認版本／prefix；版本不符就失敗／重新確認，不偷偷換件或少交。
4. **Given** 同 Shell 跑於兩個 App 且提示可偽造，**When** 限定 Warp，**Then** 只有可信正向身分可記；unknown／conflict 不回退為全記，也不宣稱隔離成功。
5. **Given** AI 執行讀檔、寫檔、搜尋、瀏覽或未知工具，**When** 分類與閱讀，**Then** 保留工具 I/O 及來源性質，不一律歸指令，也不冒充已保存檔案或觀測網路。
6. **Given** Unicode／ANSI 轉換或附件被清理，**When** 開內容命中／標記，**Then** 使用版本化座標還原；不可精確定位時明示範圍／原件不可用，不指到同名替代檔。
7. **Given** 切專案、排除 Session 或暫停時仍有在途資料，**When** 後端確認新邊界，**Then** 不保存禁止區間新原文，不改歸目前專案，也不在恢復後補讀。

### Edge Cases

- 同一 PID／相同文字在不同 Session 重複；結果跨頁、亂序、重送、缺少起點或結束。
- Shell 在背景印字、PTY 合併輸出、遠端互動、零輸出與沒有擷取輸出。
- 未知第三方來源或無法辨識的 AI 工具；不因缺少專屬介面而隱藏事件。
- 群組跨時間條件，相關背景未命中；不把相關背景當成額外命中或默認整個 Session 匯出。
- 大檔、預覽限制、實際截斷、已清理／遺失／無法讀取附件、索引尚未完成或失敗。
- 暫停後延遲送達、專案切換時未完成輸入、匯出時持續有新資料、更新／退出時仍在記錄。
- 無 Scope、未知目標、規則後來重算、私人流量；閱讀條件不改變擷取授權。
- 大量即時新增、字型／語言／縮放變更、快速切換結果、查詢回覆順序反轉。
- 相同 Tool ID 跨 provider／Session、同鍵內容衝突；Result 先到與孤立事件後續建立可靠關聯。
- Terminal App 環境提示與真實來源衝突、tmux／SSH／WSL 來源鏈中斷、PID 重用。
- 同大小檔案改寫、live prefix 追加、跨目標 cast、匯出中切專案及政策收緊。
- UTF-8／UTF-16／正規化位置不同、CRLF／ANSI 轉換、跨實體 cast 分段及清理後索引陳舊。

## Requirements *(mandatory)*

### Functional Requirements

#### 操作與導覽

- **FR-001**: 完整覆蓋接入、背景記錄、查找交付三階段；可靠性與既有基本能力優先於導覽替換及視覺精修。
- **FR-002**: 以五個主要工作入口、選用 Terminal、固定 Settings 為目標；現有十一個工作頁的能力須有明確承接位置，完成對等驗收才移除舊入口。
- **FR-003**: 活動工作區提供活動列表、輸入／輸出、AI 對話；不建立主動聊天、模型控制或另一套 AI 隱私管理頁。
- **FR-004**: 外部終端優先；Bash／Zsh／PowerShell 接入採一致操作，自動辨識並可手選。Shell 與 Terminal App 選擇分開；WSL 是環境，不是額外 Shell。
- **FR-005**: 從總覽的問題直達對應設定／修復；日常不強迫重走首次引導，HTTPS、Scope 與選用來源不阻擋終端先工作。
- **FR-006**: 一個來源只有一個主要操作入口；設定與閱讀過濾清楚區分，篩選目標／Session 不得暗中修改錄製歸屬或來源授權。
- **FR-007**: 導覽、指令面板、鍵盤及返回使用一致目的；返回保留查詢、選取、Session 與閱讀錨點，且限定於原專案。

#### 活動與來源事實

- **FR-008**: Activity 僅為可追溯顯示群組，保留原始來源事件與配對依據；不更動原始事件、保存層級或雜湊。
- **FR-009**: 操作類型、AI 提供者、發起者、觀測來源及 Session 可獨立辨識；無依據的欄位標未知，不從時間／文字相近推定同一操作。
- **FR-010**: 指令起訖與工具輸入／結果按穩定來源身分配對，缺少可靠身分就保留未配對；PID＋指令文字不能單獨作唯一依據。
- **FR-011**: 正常操作以摘要呈現，完整事件可深入；暫停、缺口、擷取／保存異常、中斷、真正 Scope 違規不得被一般噪音折疊隱藏。
- **FR-012**: 列表有穩定時間順序與同時事件排序，來源時間與接收時間可區分；晚到結果不得造成重複操作或打斷閱讀。
- **FR-013**: 沒有結束／結果紀錄不等於仍在執行或已失敗；工具回報的成功與獨立執行事實分開。
- **FR-014**: 未知來源保留通用檢視、原始欄位、證據參照與查找方式；不得因沒有專屬版型而消失。

#### 查詢與計數

- **FR-015**: 活動頂部提供一個專案搜尋及類型、來源、時間、目標四個常用條件；其餘條件按需展開，保留進階語法能力。
- **FR-016**: 搜尋與條件採交集，同維度複選採聯集；條件為可移除標籤，只有實際支援的條件可套用，不靜默忽略。
- **FR-017**: 查詢涵蓋專案的支援資料，分頁與統計先套用全部條件；不得對已載入的一小頁作篩選而宣稱完整。
- **FR-018**: 原始命中數、顯示群組數、已載入數及相關背景分開；無法得知總數時明示有更多／部分結果，不編造全域群組總數。
- **FR-019**: 命中折疊內容時定位原始片段並展開；查詢取消、失敗、零結果、未索引及受限覆蓋各自呈現，不把失敗轉成空結果。
- **FR-020**: 保留錄影與長內容搜尋能力；條件無法適用某索引時，不混入未篩選命中，並提供可理解的限制及恢復操作。
- **FR-021**: 同一查詢在切模式／跨頁跳轉／匯出時保持語意；新條件使舊回覆失效，不能被較晚返回的舊查詢覆蓋。

#### 讀取與即時更新

- **FR-022**: 指令、Tool Input／Result、HTTP 內容及已保存輸出可從來源附近直接開啟完整檢視；支援側欄及全寬，保留同一內容與位置。
- **FR-023**: 長內容分段讀取，支援範圍明確的內容搜尋、選取及複製；不得為顯示全部而一次載入無界資料。
- **FR-024**: 預覽受限、原始內容真正截斷、僅中繼資料、尚未載入、未擷取、未解密、保存失敗、附件已清理／遺失皆須區分。
- **FR-025**: stdout／stderr 只有存在順序依據才可合併；合併 PTY 畫面保留其性質。觀測指令字串不等於記錄所有 stdin，密碼輸入不因本改版自動攔截。
- **FR-026**: 新資料增量合併，預設不搶走閱讀位置；「跟隨最新」由使用者控制，新資料計數不冒充全專案總數。
- **FR-027**: AI 長文可閱讀、工具輸入／結果可展開，Thinking 預設不顯示且依實際保存能力呈現；不得聲稱取得未公開的內部推理。

#### 接入、權限與狀態

- **FR-028**: 內建擷取不要求安裝外掛，但必要依賴仍須如實準備；只提供來源真的支援的接入、啟動、驗證與修復操作。
- **FR-029**: 本機安裝、專案授權、程序狀態及實際保存證明各自可辨識；收到指令不冒充收到輸出，監聽成功不冒充 HTTPS 已解密，安靜不直接判失敗。
- **FR-030**: 官方 AI 整合預設不安裝、不授權；安裝不等於安裝 AI 工具，授權以本專案工作目錄與啟用邊界限制，Session 排除只能縮小權限。
- **FR-031**: 讀取設定不產生安裝／啟動／保存副作用；本機與專案範圍明示，儲存中／成功／失敗／重試一致，失敗不清掉使用者輸入。
- **FR-032**: 停止、暫停、卸載、清除資料的後果不同；安裝／權限／依賴需要的系統操作只在明確動作後執行。移除整合不刪來源工具原始對話及既有證據。
- **FR-033**: 新來源沿用必要的共同操作語彙及通用狀態；第三方宣告不得任意注入介面程式碼或自動執行安裝指令。

#### 證據與交付

- **FR-034**: 證據區保留截圖／附件、Marker、Bookmark、Loot 的不同語意；Loot 不是已確認漏洞，檔案變更通知不是已保存的檔案版本。
- **FR-035**: 輸出片段標記保留來源事件、可取得的附件／內容位置與選取內容；無法穩定定位就明示限制，不造假精確偏移。
- **FR-036**: 點擊一般資料列開詳情；跳到另一工作區的動作明確，返回仍可回原事件／命中／內容位置；HTTP 保留獨立專業檢視空間。
- **FR-037**: 匯出區分目前查詢、明確選取、整個 Session 及全部專案；展開、收合或切閱讀模式本身不改選取集合，相關背景不自動變成整個 Session 交付。
- **FR-038**: 沿用同一預覽與執行契約，包含原始事件、必要伴隨資料、附件排除及已知缺口；主路徑為證據包／HAR，其他現有格式放進階，成品可重新找回。
- **FR-039**: 網頁 Scope 用於網頁閱讀／交付，未設定可明示後確認匯出；不得自動作為丟棄命令的規則，也不宣稱能清乾淨截圖／錄影。重算判定與當時判定、未知與無已觀測違規分開。

#### 元件與系統表面

- **FR-040**: Settings 以擷取來源、專案與範圍、資料與隱私、介面與操作、進階與系統五分類為目標；重新分組不改變既有設定的實際儲存範圍。
- **FR-041**: HUD 保持預設開啟及獨立 IP 用途；保留穿透／恢復／焦點與單一標記入口，不擴充成迷你 Dashboard，也不強迫開專案才能看 IP。
- **FR-042**: 沿用既有設計系統、深色及紅色識別；用排列、間距、標籤與狀態表達，避免重複副標題、說明段落及為裝飾新增的卡片。
- **FR-043**: 最小支援視窗、高縮放、繁中／英文、鍵盤、空／載入／失敗／禁用狀態均可完成核心任務；必要安全警告及可存取名稱不得被精簡掉。
- **FR-044**: 證據內容安全呈現，原始 bytes 保留；不得因閱讀而執行命令、寫剪貼簿、載入外部追蹤內容或改動系統設定。
- **FR-045**: 沿用既有退出與更新流程，完成下載不代表必須重啟；保留取消、收尾失敗及更新後真實能力狀態，不以還原介面冒充還原原 PTY／網路 Session。

#### 跨層一致性補充

- **FR-046**: Activity 必須具有穩定、可重建的投影身分及來源參照；晚到／重送／亂序／翻頁不得造成同一已確認操作重複或原事件無法定位。缺可靠鍵、衝突及配對狀態依 C1 處理。
- **FR-047**: 每種可搜尋內容須提供覆蓋範圍、索引狀態／資料邊界及定位能力；Event、sidecar、stdout／stderr、cast 與附件內容分開判定。未索引、不支援或失敗不得默認為零結果。
- **FR-048**: 匯出確認時固定查詢、原始事件、必要伴隨資料、政策及附件版本／prefix；持續新增不擴大集合，來源改寫或政策收緊必須使舊確認失效或回具體失敗，不靜默換件／少交。跨目標 Session 附件另按 C5 明確選取。
- **FR-049**: Terminal App 限定擷取須有可驗證來源身分、適用範圍及繼承邊界；環境提示不能單獨作隔離證明。未知／衝突時不得退回全記或宣稱已隔離，變更亦須影響現有來源及待寫入資料。
- **FR-050**: AI Tool 除執行指令，須支援檔案讀寫、搜尋、瀏覽／網路、自訂及未知操作的通用分類與 I/O；不得一律當成 Command，或把工具回報升格為獨立觀測／已保存產物。
- **FR-051**: Shell、AI、HTTP 閱讀共用長內容分段、完整保存範圍內搜尋、選取／全量複製、位置復原、版本及來源完整性契約；呈現可不同，不能各自將有限預覽冒充全部內容。
- **FR-052**: 證據片段保存來源、版本、座標種類及實際可用的定位依據；raw bytes、正規化文字與 cast 時間／分段座標不得混用。內容轉換、改寫、清理或不可讀時明示精度與限制，原標記仍可追溯。
- **FR-053**: 專案切換、來源重啟、授權變更、Session 排除及暫停／停止須有明確生效邊界、歸屬與可驗證後果；在途／延遲資料不得繞過新邊界、保存被拒原文或默默歸入目前專案。

### Key Entities

以 [既有術語表](../../docs/domain/glossary.md) 為準；下列描述限定閱讀與操作契約，不建立第二份證據來源。

| 概念 | 本規格需要的資訊與邊界 |
| --- | --- |
| Project | 授權測試與資料／交付邊界。 |
| 工作階段 | 終端、工具或 AI 的來源工作階段；與 RedLog 程序內部 Capture Session 分開，一個工作階段可涉及多目標。 |
| Event | 已保存的來源事件；身分、時間、保存層級及原始關係保留。 |
| Activity | 可引用多筆 Event 的閱讀投影；具有穩定身分、配對狀態、來源參照及命中資訊。 |
| Evidence | 支撐事件的輸出、錄影、HTTP 內容、截圖或附件；目前可讀程度與保存／清理狀態分開。 |
| 查詢上下文 | 專案、文字、條件、結果邊界、覆蓋及原始命中；與相關背景分開。 |
| 閱讀錨點 | 來源事件、Session、附件及可用內容位置；不以儲存原文到全域介面偏好代替還原位置。 |
| 來源狀態 | 安裝、權限、運作、實際保存及錯誤；沿用來源生命週期，不創造綜合覆蓋分數。 |
| 匯出選取 | 經確認的事件、必要 companions、政策及附件版本／prefix，與閱讀布局、群組及私人書籤分開；C5。 |
| 錄製 Binding | 來源 Session 在特定 project／授權 generation 下的保存邊界；來源工作階段可以延續，binding 不能默默改歸；C6。 |
| 搜尋覆蓋 | 每種內容／版本／索引範圍與條件適用程度；不等同原件已保存；C2。 |
| 內容版本與座標 | Viewer 及片段參照的來源版本、表示與位置精度；不能用顯示字元 index 冒充 raw bytes；C3／C4。 |

## Success Criteria *(mandatory)*

### Measurable Outcomes

以下為**驗收目標，尚未量測**。測試方法、資料與平台界線見 [acceptance.md](acceptance.md)。

- **SC-001**: 五名未使用 RedLog 的受測者中至少四名，在無口頭指導下，從已安裝 App 首次啟動至證明自己終端的指令、輸出與結束碼，主動操作時間不超過五分鐘；總經過時間及依賴下載／系統授權等待另行完整記錄。
- **SC-002**: 同一批至少四名能完成選定用戶端的 HTTPS 驗證，並正確分辨代理啟動與已解密；所有提供的故障 fixture 都有可達的對應修復動作。
- **SC-003**: 從總覽找回昨天已知掃描的指令、保存輸出、時間及來源，至少四名在六十秒、四次主要啟動／導覽動作內完成；輸入字元不逐鍵計次，規則對新舊版一致。
- **SC-004**: 至少四名在九十秒內找出指定 AI Session 的 Prompt、工具參數／結果及最後回答，並正確辨識 AI 回報與獨立觀測的差別。
- **SC-005**: 對每個固定查詢 fixture，完整翻頁後的原始命中集合、群組來源及匯出集合與預期完全一致；未批准的事件、附件、私人資料及跨專案內容誤交付為零。
- **SC-006**: 十 MiB 已保存輸出及跨檔錄影均可定位已知片段；全部片段可取回，預覽限制不冒充保存截斷。記錄二十次切模式／側欄全寬／返回，閱讀錨點皆保留。
- **SC-007**: 在十萬原始事件固定資料、指定同一基準機器做三十次代表性查詢，首批正確結果的 p95 不超過一秒；同環境相較改版前的查詢與輸入延遲不得有超過 10% 的可重現退步。
- **SC-008**: 閱讀舊資料時新增一百筆事件，選取及首個可見內容錨點不變；啟用跟隨最新後才移動。兩種模式都不漏收已確認保存的紀錄。
- **SC-009**: 最小 800×500 桌面視窗及指定高縮放矩陣，可用鍵盤完成接入、讀取及匯出；沒有不可達的主要動作、遮蓋或整個視窗的非必要橫向捲動。
- **SC-010**: 已接入且正常的三十分鐘支援情境，不要求逐條操作 RedLog、切模式或手動保存；重啟後已確認保存的 fixture 可讀且交付一致，未支援或故障區間如實標明。

## Assumptions

- 本文件是目標規格；實作進度與候選證據見 verification.md。局部來源／配對驗證不等於整套工作區已改版、全平台已驗收或已發版。
- 五主要入口是資訊架構目標；取代舊 Search／Transcript 入口前，先證明搜尋覆蓋、完整閱讀、定位與交付對等。過渡期不把兩套主要查詢介面永久並列。
- 外部終端優先；只設計 Bash／Zsh／PowerShell，其他環境與擷取限制沿既有能力。不新增遠端 hook 或框架專屬解析器。
- 網頁 Scope 不自動套用指令；Target 仍可作標註與閱讀維度。IP 曝光安全判定與授權範圍不同，不因設定重分組混成一種規則。
- 保留既有敏感來源的明確選擇；AI、Clipboard、Process／Connection 監看及自動 Loot 不因改版預設啟用，也不無提示覆寫使用者既有選擇。
- 不新增 SIEM、Burp 操作／重送／掃描能力、案件管理、漏洞評分、報告產生器、報告模式、flag／proof、外掛商城或第三方 UI 程式碼宿主。
- 不以本規格搬遷證據或來源工具資料、不新增保存位置遷移、不恢復舊 hook／舊 hash 相容層。
- 不以本規格新增手機產品、未支援 OS／主題或主動 AI 聊天；現有桌面最小尺寸及高縮放仍須可用。
- [#317](https://github.com/guan4tou2/REDLOG/issues/317) 的紀錄優先順序仍成立；[#290](https://github.com/guan4tou2/REDLOG/issues/290)、[#291](https://github.com/guan4tou2/REDLOG/issues/291)、[#292](https://github.com/guan4tou2/REDLOG/issues/292)、[#296](https://github.com/guan4tou2/REDLOG/issues/296) 沿原工單追蹤，不以 UI 設計替代可靠性或平台驗收。
